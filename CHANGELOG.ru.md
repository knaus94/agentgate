# История изменений

[English](CHANGELOG.md)

## 0.14.0

- CLI, состояние/жизненный цикл/доказательства, provider adapters, аккаунты, конфигурация и терминальная
  панель разделены на модули с отдельными обязанностями.
- Добавлены группы `task`/`setup`, безопасная справка, строгие флаги/JSON, `config validate`, продолжение
  прерванного раунда через `continue`, JSON-снимки панели и адаптивный безопасный терминальный вывод.
- Исправлены оправдание ошибок baseline, повторное принятие устаревших квитанций, чтение повреждённого
  состояния, саморевью после fallback, потеря сессий, гонки отмены и скрытые ошибки записи.
- Выпускная проверка дополнительно исправила требование writable state для чтения конфига, обход актуальности
  архитектуры при продолжении/ответе исполнителю и потерю владения файлами при повреждённом состоянии соседа.
  В браузерной фикстуре убраны повторные аргументы; строгий парсер сохранён.
- Git landing защищает чужие staged/пользовательские изменения; очистка worktree ограничена управляемыми
  путями. MCP writable не выходит через symlink, Figma-профили скрываются после остальных mounts.
- Credentials воркеров изолированы с проверяемой обратной записью refresh; исправлены окна квот,
  дубликаты подписок, кэш probes, конфликты окружения и маршрутизация аккаунтов/моделей.
- Добавлен официальный REST-транспорт Figma, атомарные проверяемые пакеты, GraphQL-записи по variables,
  явные ошибки пропуска фикстур и ограниченная остановка собственных стендов; улучшены замеры цветов.
- Усилены загрузка/установка/обновление; сравнение SemVer исключает случайный downgrade.
  Добавлены полный ZIP, локальная установка, checksum и руководства по миграции/архитектуре/проверкам.
- Изменены frontend-маршруты heavy/ultra, чтобы автор не совпадал с ревьюером по умолчанию.
  Удалены непроверенные бенчмарки и цены из документации моделей.

Точная область изменений и ограничения: [release notes](RELEASE_NOTES.md), [validation](docs/validation.md).

## 0.13.0

- Проектные правила и критерии локальных skills передаются подготовщику, архитекторам, разведке и UI-дизайнеру
  с известной областью файлов, а также писателям и ревьюерам. Подготовка показывает применимые правила,
  области, файлы инструкций и источники. Недоступные обязательные файлы дают понятный BLOCKED до сохранения плана.
- Изменение правил делает неактуальными принятое архитектурное решение и кэш разведки. Приёмка использует
  существующие review rules; новый менеджер skills, зависимости и дополнительные воркеры не добавлены.
  Старым архитектурным квитанциям с применимыми проектными правилами нужен новый проход для этой привязки.
- Порядок настроек: пользовательские расширения/конфиг, проектные расширения/конфиг, личный конфиг checkout
  поверх встроенной таблицы/профиля. **Явные списки в конфиге заменяют значения расширений**; списки расширений
  по-прежнему дополняются. `config extensions` показывает итоговые правила и цепочку источников.
- Измеритель получает настройки стенда из того же конфига CLI, включая личные переопределения, для репозитория
  выбранного экрана. Отдельный алгоритм слияния настроек в JavaScript не добавляется.
- Встроенный skill описывает работу с пакетом макета и доказательствами. Компоненты, CSS-подход, токены
  и семантика контролов следуют правилам проекта и принятой задаче, а не частным предписаниям из одного интерфейса.

## 0.12.0

- Приёмка макета использует существующие review rules: внешний вид и кадрирование, размещение в оболочке,
  семантика контролов, покрытие и исключения. Одних зелёных измерений для закрытия задачи недостаточно;
  отсутствие доказательств блокирует приёмку. Правила оценивает тот же ревьюер, дополнительный агент не нужен.
- Экспорт Figma использует геометрические границы узла и сохраняет родительский экран. Измеритель сохраняет
  выбранный блок и всю страницу вместе с координатами корня. Изменение этих доказательств отменяет прежнюю
  приёмку. Старые пакеты со ссылкой и без контекста перевыгружаются без замены исходной baseline задачи.
- Измеряются размеры корня без заливки и отсутствие border. Пиксельное сравнение учитывает недостающую или
  лишнюю область изображения, а не обрезает обе стороны по меньшему снимку. Отчёт отделяет PASS измерений
  от независимой визуальной приёмки.
- Инструкции сохраняют семантику input при недоступном API и ограничивают вывод об адаптивности реально
  проверенными ширинами/состояниями, включая согласованные проверки брейкпоинтов.

## 0.11.0

- Для телефона и планшета добавлен явный режим `device: mobile`, независимый от CSS viewport. Отчёт показывает
  ширину документа, размеры и padding корня, overflow. Десктопный scrollbar gutter больше не приходится
  принимать за дефект мобильной вёрстки. Режим устройства входит в контракт baseline и ревью.
- `map.select` разрешает уникальные CSS-селекторы; явное соответствие не скрывает неправильную геометрию.
  Разные слои artwork больше не получают автоматически один элемент. Неоднозначный селектор — ошибка настройки.
- Подготовщик возвращает технический BLOCKED без обязательных вопросов к пользователю. При исправлении
  измерения используются выбранные макеты и факты гейта о наблюдениях/baseline; Figma повторно не открывается
  без запроса. Инструкции объясняют сопоставление padding и разницу между проверкой макета и поведения.
- Приостановленное исправление после явного resume можно перепланировать, сохранив исходный снимок и замечания.
- Проверки с `no_reuse` повторяются при ревью даже без изменения исходников; изменившийся снимок страницы
  делает визуальное ревью неактуальным вместо повторного использования старого наблюдения.
- Сценарии проверяют телефон 390px, планшет 768px, десктопный gutter, границы с padding и сопоставление изображений.

## 0.10.0

- **Подготовку выполняет воркер.** `prepare` получает ограниченный каталог макета и поручает читающему
  воркеру исследование репозитория и составление плана. Его карта переиспользуется при реализации; лид решает
  продуктовые вопросы и согласует ресурсы. Писателям больше не выдаются служебные layout-команды гейта.
- **План активной задачи можно исправить.** `replan` сохраняет идентичность задачи, исходный снимок кода и
  замечания, заменяет служебные проверки и требует нового ревью. Root и другие параметры доходят до измерителя;
  подготовка возобновляется после сбоя без новой baseline по готовому коду. Ошибки стенда не отправляются CSS-писателю.
- Проверка макета закрывает браузер и свой стенд при ошибке и отмене, читает фикстуры без создания каталога
  и связывает исключения baseline с контрактом измерения и точным расхождением.
- Перед выпуском выполняются Go-регрессии и сценарий настоящего Chromium; версия браузерного инструмента закреплена.

- Требования получают отдельные доказательства приёмки в обычных и поэтапных задачах. Гейт проверяет ссылки
  на код, актуальные успешные квитанции команд и наблюдения браузера; частичное или отсутствующее доказательство
  не позволяет завершить задачу. Виды команд различают тесты, типы, линт, сборку, измерения и runtime-проверки.
- Расширения подключают `review_rules` по области файлов, с обязательным или рекомендательным результатом.
  Их оценивает существующий ревьюер. Изменение инструкций и доказательств требует новой оценки; недоступное
  обязательное правило блокирует работу. `review {recheck: true}` запрашивает новую оценку без обхода гейта.
  Планы без этих критериев работают как раньше; задачи с requirements требуют структурированного ревью.
- Правила простоты оценивают пользу абстракции, а не только число вызывающих, и различают оправданное
  восстановление на внешней границе и fallback, который скрывает сломанный основной контракт.

## 0.9.11

- Задача, продолженная на гейте, который открылся до того, как её макет удалось замерить, больше не проваливает
  проверку вёрстки из-за отсутствующей записи: без записи засчитывается каждое расхождение. `agentgate layout
  --help` — не ошибка.

## 0.9.10

- **Можно верстать страницу, которой ещё нет.** Замер до работы больше не падает, когда страницы или её
  корневого элемента нет, а страница, показывающая почти ничего из макета, считается непостроенной: ничто из
  отсутствующего не засчитывается как известное.
- Экран с описанием, но без макета, достраивается по ссылке `figma` при запуске.
- На ссылку на страницу или секцию Figma, а не на кадр, команда отвечает списком кадров; две команды Figma
  одновременно ждут друг друга, а не падают; `agentgate figma --help` — не ошибка.
