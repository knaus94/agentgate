# Изолированные задачи

[English](../isolation.md)

По умолчанию писатели правят вашу рабочую директорию: вы видите, как растёт изменение, а две сессии не могут
владеть одним файлом. С флагом `-w` задача работает в другом месте, и ваша директория меняется только тогда,
когда вы это разрешите.

```
/dev -w добавь ограничение частоты на эндпоинт экспорта
/dev -w -h переведи суммы счетов в целые копейки      # другая сессия Claude Code, тот же репозиторий
```

## Что происходит

1. **Старт.** Инструмент создаёт ветку `dev/<задача>-<id>` от вашего текущего `HEAD` и git worktree для неё в
   `~/.local/state/agentgate/…/worktrees/`. Ваши незакоммиченные правки в неё не попадают.
2. **Работа.** Писатели, объявленные проверки и ревьюеры работают внутри этого worktree. Для воркеров в
   песочнице ваша директория доступна только на чтение. Правки исходников задачи появляются в worktree;
   существовавшие незакоммиченные правки остаются в вашей директории. У скриптов подготовки и явно общих
   каталогов свои разрешения.
3. **Несколько задач.** У каждой сессии свой worktree и своя ветка, поэтому задачи могут менять одни и те же
   файлы. `agentgate watch` и `agentgate status` в репозитории показывают их все.
4. **Завершение.** Задача проходит обычный гейт — проверки, ревью, триаж — и коммитится в свою ветку. Лид
   сообщает, что сделано, и спрашивает, как влить результат.
5. **Вливание**, по вашему слову:

   | `land` | Результат |
   |---|---|
   | `apply` (по умолчанию) | изменение появляется в вашей директории **незакоммиченным**; вы читаете его и коммитите сами |
   | `commit` | то же, но с коммитом в текущую ветку с итогом задачи (ваши хуки выполняются) |
   | `branch` | директория не трогается; ветка `dev/…` остаётся под pull request |
   | `drop` | работа выбрасывается |

   После этого worktree удаляется, ветка — тоже, если вы не выбрали `branch`.

## Если ваша директория ушла вперёд

Пока задача работала, влились другие задачи или вы сами что-то закоммитили. Перед вливанием ваш текущий `HEAD`
сливается в задачу **внутри её worktree**:

- **Слияние чистое, файлы другие.** Все объявленные проверки запускаются заново на слитом коде. Зелёные —
  задача вливается.
- **Слияние чистое, но новые коммиты изменили файлы, которые меняет и задача.** Слитый результат — не то, что
  проходило ревью, поэтому задача открывается заново для ревью разницы и затем вливается.
- **После слияния падает проверка.** Задача открывается заново; ошибка уходит писателям в их сессии.
- **Конфликт.** Маркеры остаются в worktree. Задача открывается заново, лид говорит, как совместить два
  изменения, и писатели — владельцы этих файлов — разрешают конфликт; дальше проверки и ревью как обычно.

Маркеры конфликтов в вашу директорию не попадают никогда. Вливание также отказывается — и ничего не меняет, —
если у вас есть собственные незакоммиченные правки в файлах, которые приносит задача: закоммитьте или спрячьте
их, либо влейте как `branch`.

`land {how: "commit"}` также отказывается, если в индексе рабочей директории есть любые подготовленные к
коммиту изменения, включая посторонние файлы. Это не позволяет включить чужие записи индекса в коммит
задачи. Сначала закоммитьте их или уберите из индекса либо используйте `apply`, сохраняющий индекс.
Новые правки в worktree завершённой задачи должны снова пройти ревью и finish перед вливанием.

## Подготовка worktree

В worktree есть только то, что отслеживает git: нет `node_modules`, сгенерированного кода и локальных
env-файлов. Опишите, что нужно свежему worktree, в `.agentgate.json` репозитория (или в пользовательском файле):

```json
{
  "worktree": {
    "copy": ["env/.env.local"],
    "setup": [["yarn", "install", "--immutable"], ["npm", "run", "local:prisma:base:generate"]],
    "setup_timeout_s": 1800
  }
}
```

`copy` переносит неотслеживаемые файлы или каталоги из вашей директории; команды `setup` один раз выполняются в
новом worktree вне песочницы, как собственные скрипты репозитория. Им доступны переменные `AGENTGATE_CHECKOUT`
(ваша директория) и `AGENTGATE_WORKTREE`. Каталог `.agentgate` рабочей директории подключается в worktree
ссылкой, поэтому планы и вспомогательные скрипты из него остаются доступны. Настройки, которые ваши, а не
командные, кладите в `.agentgate/config.json`. Упавшая команда подготовки останавливает
запуск и удаляет worktree. `"default": true` изолирует каждую пишущую задачу без флага.

Не подкладывайте `node_modules` из рабочей директории ссылкой в монорепозитории с workspace-пакетами: пакеты в
нём указывают на исходники рабочей директории, и проверки молча тестировали бы не тот код. Устанавливайте — или,
если зависимости рабочей директории актуальны и она на той же файловой системе, копируйте их жёсткими ссылками:
содержимое файлов будет общим вместо создания копий, а относительные ссылки workspace-пакетов будут
указывать внутрь worktree:

```json
{"worktree": {"setup": [["sh", "-c", "cp -al \"$AGENTGATE_CHECKOUT/node_modules\" node_modules"]]}}
```

Файлы под жёсткими ссылками общие с рабочей директорией: для чтения это нормально, для задачи, меняющей
зависимости, — нет.

## Ограничения

- Изолируются только файлы. Порты, локальные базы и запущенные сервисы общие: две задачи, работающие с одним
  локальным стендом, будут мешать друг другу.
- Worktree с установленными зависимостями стоит времени и места. Для мелкой правки обычный режим дешевле.
- `-w` — для задач, которые пишут код. `review` и `clean` оценивают то, что уже лежит в вашей директории.
- Одна сессия ведёт одну задачу: влейте или выбросьте завершённую изолированную задачу, прежде чем начинать
  следующую в этой сессии.
- Завершённая, но не влитая работа автоматически не удаляется.
