# Расширения

[English](../extensions.md)

Расширение — один JSON-файл, который подключает что-то к `agentgate`, не трогая ни его исходники, ни ваш
основной файл настроек: граф кода для воркеров, индекс рабочего пространства, то, что нужно для них в worktree.
Положили файл — включено; убрали (или переименовали так, чтобы имя не кончалось на `.json`) — выключено.

```
~/.config/agentgate/extensions/*.json       ваши, для всех репозиториев
<репозиторий>/.agentgate/extensions/*.json  для одного репозитория (переезжают вместе с планами при синхронизации каталога)
```

```sh
agentgate config extensions    # какие файлы загружены и что добавляет каждый
agentgate config show          # настройки после их слияния
```

В расширении лежат обычные ключи настроек. Объекты вливаются в настройки ключ за ключом. Списки **дополняют**
уже имеющийся список, поэтому два расширения могут каждое принести свой файл для worktree, ничего не зная друг
о друге. `about` — пояснение для людей. Аккаунты расширением задать нельзя.

## Проектные правила ревью

`review_rules` добавляет локальные инструкции к существующему ревью. Писатели получают те же применимые
правила; первый ревьюер оценивает их вместе с критериями приёмки. В light это делает лид.

```json
{
  "about": "Public-contract review for the application",
  "review_rules": {
    "contracts": {
      "instructions": ["docs/review-contracts.md"],
      "files": ["src/api/**", "src/shared/**"],
      "mode": "blocking"
    }
  }
}
```

- `instructions` — непустые локальные файлы, в том числе подходящий `SKILL.md`. Относительные пути считаются
  от корня checkout; допустимы абсолютные пути и `~/`. Вспомогательные документы перечисляются явно.
  Содержимое сохраняется в задании: чтение навыка не подключает плагины и не запускает его процесс работы.
- `files` — область объявленных файлов задачи, выбранная шаблонами `*`, `?`, `**`. Без неё правило относится
  ко всем задачам. Неприменимое правило не загружается. Лучше хранить инструкции в Git, чтобы они были в worktree.
- `mode` — `blocking` по умолчанию или `advisory`. Обязательное правило требует `pass` либо обоснованного
  `not_applicable`. Недоступные обязательные инструкции блокируют работу; рекомендательные остаются в отчёте.

Добавление, изменение или удаление применимого правила требует нового ревью. Инструкции не дают новых
инструментов, тестов, серверов или разрешений. Дополнительные процессы моделей не запускаются.
Дефекты кода по-прежнему проходят через замечания и триаж; рекомендательное правило не понижает важность
дефекта, найденного по встроенной оси ревью. Форматы результата и доказательств описаны в `agentgate reference`.

## Инструменты для воркеров

Воркеры намеренно работают без ваших MCP-серверов и плагинов: ревью не должно зависеть от того, что
установлено на одной машине. `worker_mcp` всё же выдаёт выбранным ролям выбранные инструменты.

```json
{
  "about": "граф кода graphify для воркеров",
  "worker_mcp": {
    "graphify": {
      "command": "graphify-mcp",
      "args": ["graphify-out/graph.json"],
      "tools": ["query_graph", "get_node", "get_neighbors", "shortest_path"],
      "roles": ["scout", "architect", "reviewer", "consultant"],
      "hint": "a graph of this repository's code. Ask it who calls a symbol before you grep.",
      "refresh": ["graphify", "update", "."]
    }
  },
  "worktree": {"copy": ["graphify-out"]}
}
```

| Ключ | Смысл |
|---|---|
| `command`, `args`, `env` | как запускается stdio-сервер MCP; он работает внутри песочницы воркера, в рабочем каталоге |
| `tools` | единственные инструменты, которые воркер может вызвать; пусто — все инструменты сервера. Ограничение действует для обоих CLI |
| `roles` | кому выдаётся: `scout` (по умолчанию), `architect`, `writer`, `reviewer`, `consultant`, `designer` |
| `hint` | когда им пользоваться; воркеру сообщается это вместе с именами инструментов (пишите по-английски) |
| `refresh` | команда, которая выполняется в рабочем каталоге один раз за операцию перед первым использованием сервера и обновляет его индекс |
| `writable` | каталоги рабочего каталога, куда сервер должен писать (кэш); читающим воркерам они открываются на запись |

Роль по умолчанию — только разведчик: он один раз составляет карту кода, и то, что он узнал, доходит до
писателей и ревьюеров через пакет контекста. В heavy и ultra разведки по умолчанию нет, поэтому инструменту,
нужному проходу дизайна, укажите роль `architect`. Ревьюерам инструмент стоит давать, когда они постоянно задаются
вопросом «кто ещё это вызывает»; писателям — только если без него они не могут работать.

Два замечания. Песочница доступна только на чтение всем, кроме писателей, поэтому серверу, который строит
индекс по требованию, нужен `writable` для каталога кэша либо `refresh`, строящий индекс заранее. И `refresh`
выполняется вне песочницы, как собственные скрипты репозитория.

## Готовые примеры

В [`examples/extensions/`](../../examples/extensions) лежат два файла, которые можно скопировать:

- **`graphify.json`** — граф кода [graphify](https://github.com/Graphify-Labs/graphify). Установите его
  (`uv tool install "graphifyy[mcp]"`), один раз постройте граф без вызовов моделей
  (`graphify extract . --code-only`), исключите `graphify-out/` из git. Расширение обновляет граф перед
  использованием (около двух секунд при готовом кэше) и копирует его в изолированные worktree.
- **`nx.json`** — граф проектов Nx через собственный `nx mcp` рабочего пространства: проекты, цели,
  зависимости. Nx пишет кэш графа, поэтому расширение открывает `.nx/workspace-data` на запись.
