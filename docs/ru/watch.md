# Терминальная панель

[English](../watch.md) · [Командный интерфейс](cli.md)

`agentgate task watch` открывает живую панель задач Claude Code и Codex. Запускайте
её внутри репозитория или через задачу `agentgate: watch` в Zed. Прежняя команда
`agentgate watch` открывает ту же панель.

Панель не управляет задачей, не запускает модели и не сохраняет состояние шлюза.
Единственное, что она запрашивает у провайдеров, — лимиты настроенных аккаунтов,
как это делает `agentgate accounts`. Её цель — показать текущий шаг, то, чего
задача ждёт, работу исполнителей, следующее действие и запас каждой подписки.

## Что отображается

| Раздел | Содержимое |
|---|---|
| Tasks | Сначала работающие задачи, затем требующие внимания, готовые изолированные изменения и недавно завершённые задачи. Режим, шаг или пауза, время и текущая операция |
| Stages | Принятые, текущая и оставшиеся части большой задачи; записанные операции и их длительность |
| Workers | Исполнитель подготовки, дизайнеры, консультанты, авторы и ревьюеры: модель, усилие, аккаунт, длительность, повторные запуски и последнее действие |
| Checks | Объявленные команды проверки, последние результаты и актуальность доказательств относительно входных файлов |
| Findings | Открытые замечания по серьёзности, заметки и число блокирующих проблем |
| Signals | Механически найденные признаки, которые должен исследовать ревьюер |
| Plan | Краткое описание, потоки, принадлежащие им файлы и принятая архитектура |
| Limits | Строка на каждый настроенный аккаунт: провайдер, имя, тариф, каждый лимит по имени и то, что инструмент делает с аккаунтом |
| Заголовок | Выбранная область и для каждого аккаунта его самый тесный лимит по имени: `main fable 72% · work2 all 12%`. Скрывается при ширине меньше 70 колонок |

### Лимиты

```
 LIMITS                                                                                        read 2m05s ago
  claude  main        max 20x     all 49% · fable 72%  kept for the lead · fable: unknown if all caps it
  claude  work2       max 5x      all 12% · fable 100% (back Nov 17 04:00)  fable resting until Nov 17 04:00
                                  fable: own limit only
  codex   codex       prolite     5h 8% · week 66%
```

`all` — общий недельный лимит подписки, у которой есть ещё и лимит отдельной модели; `week` — недельный
лимит подписки без такого; имя модели — её собственный лимит; `5h` — сессионное окно. У лимита от 80%
показано время сброса. После лимитов коротко сказано, что инструмент делает с аккаунтом: оставлен лиду,
отдыхает и до какого времени, вход не выполнен, та же подписка, что у другого аккаунта, и что известно о
собственном лимите модели ([аккаунты](accounts.md#собственные-лимиты-моделей); `agentgate accounts`
говорит то же полными фразами). Пометки, не поместившиеся рядом с лимитами, продолжаются на следующей
строке. `read … ago` — возраст самого старого из показанных чтений.

Блок уступает место задачам: при высоте меньше 24 строк или когда задачи и выбранная задача занимают
экран, остаётся только цифра в заголовке. `L` скрывает и показывает блок. Без настроенных аккаунтов блока
нет.

В узком терминале строки задач и исполнителей занимают две строки. При небольшой
высоте область просмотра следует за выбранным элементом: проверки и исполнители
доступны даже ниже первоначального экрана. Размер можно менять во время работы.
Повреждённое или недоступное состояние показывается отдельной строкой с ошибкой,
а не вызывает падение или видимость отсутствия задачи.

## Клавиши

| Клавиша | Действие |
|---|---|
| `↑` / `↓` или `k` / `j` | Перейти между задачами или строками |
| `Tab`, `←` / `→` или `h` / `l` | Переключиться между списком задач и её элементами |
| `Enter` | Войти в задачу или открыть выбранный элемент |
| `Esc` / `h` | Вернуться из деталей |
| `PgUp` / `PgDn`, `Space` | Перейти на страницу |
| `Home` / `End`, `g` / `G` | В начало или конец списка; в деталях конец возобновляет слежение |
| `f` | Следить за новыми действиями исполнителя в открытых деталях |
| `a` | Переключить текущую рабочую копию и все копии |
| `L` | Скрыть или показать лимиты аккаунтов |
| `r` | Обновить немедленно, включая актуальность проверок |
| `?` | Открыть подсказку по клавишам |
| `q` / `Ctrl-C` | Закрыть панель |

Открытая активность исполнителя следует за последними событиями. Прокрутка
останавливает слежение, `f` возобновляет его. Исполнитель привязан к каталогу
своего запуска, поэтому новая волна ревью не подменяет незаметно уже открытого
исполнителя.

| Открытый элемент | Детали |
|---|---|
| Исполнитель | Команды с концом вывода, прочитанные и изменённые файлы, сообщения модели и финальный отчёт |
| Проверка | Вывод последнего сохранённого запуска |
| Замечания | Серьёзность, место, доказательство, последствия, предлагаемое исправление и решение ведущего |
| Сигналы | Подсказки механического анализа, не выдаваемые за подтверждённые дефекты |
| План | Описание, задания и файлы потоков, принятый дизайн |

Активность читается из потока событий каждого CLI. Длинные внутренние пути
сокращаются до `task:/…`, `worktree:/…` и `state:/…`. Управляющие терминальные
последовательности из вывода исполнителей удаляются, включая команды буфера
обмена и заголовка окна. Вставленный текст не запускает клавиатурные команды.

## Обновление и актуальность

Активность исполнителей и состояние обновляются каждую секунду, а файлы
перечитываются, только когда изменились: поток событий исполнителя дочитывается с
места, где закончилось прошлое чтение, и между изменениями перерисовка не читает
содержимого файлов. Актуальность проверок — для неё git записывает одно дерево
рабочей копии — оценивается при изменении состояния задачи, по клавише `r` и раз в
30 секунд для незавершённой задачи, пока операция не идёт; идущая операция
проверяет сама. Навигация по строкам не запускает повторное сканирование
репозитория.

Идущая операция пишет под строкой задачи, чем занята и сколько: `now: check 4 of
7: yarn nx run client:test …`, `writing: api (sol:xhigh)`, `review: correctness
(opus:high)`; `status` показывает то же в `running.now`, а `watch --json` — в поле
`now` задачи. Сам шлюз каждый раз проверяет
доказательства перед зависящей от них операцией: кеш панели не разрешает
завершение задачи.

Показанные лимиты — сохранённые последним чтением, кто бы его ни сделал: вызов
исполнителя, `agentgate accounts` или сама панель. Пока панель открыта, она
перечитывает лимиты аккаунта, чьё чтение старше пяти минут, по одному аккаунту за
раз, в фоне; перерисовка никогда не ждёт провайдера. Это тот же запрос, что делает
`agentgate accounts`: для Claude — запрос использования с токеном профиля, для
Codex — локальный `codex app-server` профиля; модель при этом не запускается.
Неудачное чтение оставляет прежние цифры и добавляет причину в строку аккаунта. `r`
провайдеров не опрашивает; сразу это делает `agentgate accounts`. `--once` и
`--json` печатают сохранённое и ничего не запрашивают.

## Текстовый и JSON-снимок

```sh
agentgate task watch --once
agentgate task watch --once --no-color
agentgate task watch --all
agentgate task watch --json
agentgate task watch --all --json
```

`--once` выводит один текстовый снимок и завершает процесс. Если stdin или stdout
не терминал, `watch` также не ждёт нажатий клавиш. `TERM=dumb` выбирает режим
снимка. `NO_COLOR` или `--no-color` выключает ANSI-цвета, сохраняя управление
клавишами в обычном терминале.

`--json` всегда возвращает один снимок для программной обработки. В нём есть
`schema_version` (сейчас `2`), `read_only`, `scope`, массив `tasks` и массив
`accounts`. У задач есть
`step`, `paused`, положение среди этапов, признак работы, исполнители, проверки,
число блокирующих замечаний и следующее действие. В версии 1 вместо `step` и
`paused` было поле `phase`. Повреждённые задачи содержат поле `error`. Внутренние объекты Gate
и полные промпты исполнителей в снимок не включаются. `accounts` — настроенные аккаунты
с сохранёнными чтениями в том же виде, что у `accounts list --json`: `windows` с `label`,
`scope`, `period`, `used_percent` и `resets_at`, а также `cooling`, `lead_only`,
`general_caps` и `probed_at`.

Без `--all` интерактивный и текстовый режимы автоматически покажут все рабочие
копии, если у текущей нет задач, а у других они есть. JSON-режим сохраняет явно
выбранную область: для всех копий нужен `--all`. Команда `task status --all`
возвращает прежний обзор текущей рабочей копии в исходном JSON-формате.
