# Режимы

[English](../modes.md)

Режим задаёт всё сразу: есть ли проход дизайна, кто пишет, кто ревьюит и какие замечания блокируют завершение.
Второй ручки нет.

## Как выбирается режим

Флаг в запросе окончателен: `-l`, `-m`, `-h`, `-x` (или `--light`, `--medium`, `--heavy`, `--ultra`).

Без флага лид записывает `assessment` — что он нашёл в коде, — и режим следует из таблицы; срабатывает первое
подходящее правило:

| № | Факты | Режим |
|---|---|---|
| 1 | назван риск **и** изменение нельзя откатить после выпуска | ultra |
| 2 | серьёзный риск (`authorization`, `security`, `money`) **и** изменение сложное | ultra |
| 3 | любой названный риск | heavy |
| 4 | сложно **и** существенная неопределённость | heavy |
| 5 | тривиально, определённо, не более 3 файлов, один поток | light |
| 6 | всё остальное | medium |

В оценке четыре факта и доказательство:

```json
{"size": "ordinary", "risks": ["data-integrity"], "irreversible": false, "uncertainty": "low",
 "evidence": "Суммы пишутся одной транзакцией в orders/service.ts; два вызывающих"}
```

Названные риски: `authorization`, `security`, `money`, `data-integrity`, `concurrency`, `migration`,
`public-contract`. Риск называется, только когда изменение действительно его затрагивает. «У модуля много
вызывающих» — не риск, а обычная работа, то есть medium.

`agentgate route --file plan.json` показывает решение и его причины до запуска чего-либо.

## Что запускает каждый режим

| | light | medium | heavy | ultra |
|---|---|---|---|---|
| Контекстный пакет | собственный контекст лида | разведка `sol:medium` | нет: принятый дизайн | нет: принятый дизайн |
| Архитекторы | лид | лид | `fable:high` ∥ `astra:high`, независимо и параллельно | `fable:xhigh` ∥ `astra:xhigh`, затем каждый критикует другой на `high` |
| Раунд блокеров | — | — | по желанию, один | по желанию, один |
| Бэкенд | `sol:medium` | `opus:medium` | `opus:high` | `opus:xhigh` |
| Фронтенд | `sonnet:medium` | `opus:medium` | `astra:high` | `astra:xhigh` |
| Ревью | лид | архитектура+простота `fable:medium` ∥ корректность `astra:medium` | архитектура+простота `fable:high` ∥ корректность `astra:high` | архитектура+простота `fable:high` ∥ корректность `fable:xhigh` ∥ корректность `astra:xhigh` ∥ безопасность `astra:high` |
| Потолок усилия | `high` | `high` | `xhigh` | `max` |
| Блокирующие уровни | P0, P1 | P0, P1 | P0, P1, P2 | P0, P1, P2 |
| Проверки для завершения | необязательны | минимум одна | минимум одна | минимум одна |
| `architecture_evidence` при завершении | — | — | обязательно | обязательно |
| Потолки процессов (дизайн / писатель / ревьюер) | по умолчанию 20 мин | по умолчанию 20 мин | 15 / 30 / 20 мин | 30 / 60 / 30 мин |

У лестницы одно правило для моделей: **создаёт сильнейшая модель, которую режим может себе позволить;
остальные фронтирные модели проверяют.** Цифры — в [Почему именно эти модели](model-selection.md).

## Как тратится усилие

Усилие рассуждения — главная ручка расхода, а лимиты конечны. Четыре правила держат его там, где оно окупается.

**1. Код читается один раз, и следующий раунд продолжает это чтение.** Дорогая модель открывает файлы сама,
какую бы карту ей ни дали: в замеренном проходе дизайна архитекторы прочитали одни и те же файлы с картой
разведчика и без неё, а карта лишь заставила их ждать. Поэтому архитекторы карту не получают. В heavy и ultra
писатели и ревьюеры начинают с принятого лидом дизайна — его делают сильнейшие модели, уже прочитавшие код. В
medium дизайна нет, и там один дешёвый быстрый разведчик один раз составляет карту области для писателей и
ревьюеров: какие файлы важны и зачем, кто их вызывает, инварианты, принятые приёмы. И ни один воркер не
начинает заново: критика и доработка продолжают сессию архитектора, исправление — писателя, перепроверка —
ревьюера.

**2. Базовое усилие следует значениям по умолчанию от производителей.** Medium запускает каждую модель на
уровне, который ставит по умолчанию её производитель. Heavy — на ступень выше, ultra — на две. В первую
очередь усилие получают дизайн и ревью корректности — они дают мало текста и решают многое — и меньше
получают полосы, которые больше читают, чем рассуждают.

**3. `max` зарабатывается, а не предполагается.** Ни одно значение по умолчанию его не использует. Усилие
писателя растёт на одну ступень, до потолка режима, только когда исправление не дало подтверждённого
прогресса, когда лид передал `escalate` в `fix`, или когда план поднял один трудный поток полем `effort`.
До `max` может дойти только ultra.

**4. Перепроверка стоит меньше, чем ревью.** После исправления заново работают только полосы, которым есть
что проверять, плюс одна полоса корректности, читающая дельту на предмет регрессий, — каждая в своей сессии
и на ступень усилия ниже. Раунд критики в ultra устроен так же относительно
раунда дизайна.

Во всех режимах: замечания P3 — это заметки без триажа; нарушение границы блокирует при любой серьёзности;
замечание, принятое лидом, блокирует до устранения.

## Почему дизайн параллельный

Дизайн, а за ним критика — это два долгих вызова подряд. Два независимых дизайна занимают время одного, а их
расхождения показывают лиду, где настоящая развилка. В ultra критика идёт вторым параллельным раундом: там
цена пропущенного блокера выше нескольких минут.

Отчёты дизайна просят держать около 800 слов, и у каждого режима свои потолки процессов
(`architecture_timeout_s`, `writer_timeout_s`, `reviewer_timeout_s`): щедрые в ultra, где усилие `max` означает
долгие ходы, и жёсткие в остальных, чтобы проход не мог незаметно занять полчаса.

## Изменить режим

```sh
agentgate config set modes.medium.review '[{"axes":["correctness","architecture"],"route":"fable:high"}]'
agentgate config set modes.heavy.blocking '["P0","P1"]'
agentgate modes
```

Пустой `review` (`[]`) означает, что дифф ревьюит сам лид, как в light.
