# Несколько подписок

[English](../accounts.md)

`agentgate` запускает CLI `claude` и `codex`, установленные на вашей машине. Каждый CLI хранит вход в каталоге
профиля: `CLAUDE_CONFIG_DIR` у Claude (по умолчанию `~/.claude`), `CODEX_HOME` у Codex (по умолчанию
`~/.codex`). *Аккаунт* — это один такой каталог. Когда у провайдера несколько аккаунтов, `agentgate`
распределяет воркеров между ними и обходит те, где квота кончилась.

Пока ни один аккаунт не настроен, ничего не меняется: каждый воркер использует профиль CLI по умолчанию.

## Настройка

```sh
agentgate accounts discover          # что есть на машине: ~/.claude, ~/.claude-*, ~/.codex, ~/.codex-*
agentgate accounts discover --save   # добавить все профили, дающие новую ёмкость
agentgate accounts                   # лимиты настроенных аккаунтов, читаются вживую
```

```
claude
  claude         ~/.claude          max 20x      5 hours 12% · week 42% · week, fable 39%
                   lead session runs here
  claude-2       ~/.claude-2        max 5x       5 hours 0% · week 8%
codex
  codex          ~/.codex           prolite      5 hours 3% · week 22%
```

Чтобы добавить вторую подписку, дайте ей свой каталог и один раз войдите в неё в терминале:

```sh
agentgate accounts add claude-2 claude ~/.claude-2
CLAUDE_CONFIG_DIR=~/.claude-2 claude auth login

agentgate accounts add codex-2 codex ~/.codex-2
CODEX_HOME=~/.codex-2 codex login
```

`accounts remove <имя>` убирает аккаунт (каталог не трогается); `accounts reset <имя>` забывает записанный
лимит, если вы знаете, что он уже восстановился. Аккаунты хранятся в пользовательском файле
(`~/.config/agentgate/config.json`, ключ `accounts`); `.agentgate.json` репозитория задать их не может —
репозиторий не выбирает, чья подписка оплачивает его работу.

`discover --save` пропускает три вида профилей, и `accounts` для каждого объясняет причину:

- **вход не выполнен** — пользоваться пока нечем;
- **та же подписка во втором каталоге** (например, облегчённый профиль Codex рядом с основным) — ёмкости она
  не добавляет, поэтому показывается, но дважды не считается;
- **профиль с API-ключом** — он оплачивается по токенам. Используется, только если вы сами добавили его с
  `--paid`, и только после подписок.

## Как вызов выбирает аккаунт

Перед началом работы у каждого аккаунта спрашивается, сколько лимитов израсходовано (показание действует две
минуты). Для каждого вызова аккаунты нужного провайдера ранжируются:

1. **Запас для этой модели.** Решает самый тесный из применимых лимитов: 5-часовое окно, недельное и
   отдельная корзина модели, если она у провайдера есть (Claude считает Fable отдельно). Аккаунт с исчерпанной
   корзиной Fable продолжает обслуживать Opus и Sonnet.
2. **Что уже запущено.** Каждый выполняющийся вызов учитывается на своём аккаунте, поэтому одновременно
   стартовавшие полосы расходятся по аккаунтам, а не садятся все на самый свободный.
3. **Аккаунт лида берегётся**, если у другого похожий запас: из него расходуется ваша интерактивная сессия, и
   он должен закончиться последним.

Дальше, когда провайдер отказывает из-за исчерпанного лимита:

```
маршрут fable:high
  аккаунт claude-2   → лимит исчерпан    отдыхает до сброса, пробуем следующий аккаунт
  аккаунт claude     → отвечает          та же модель, без замены
  (все аккаунты исчерпаны) → объявленная замена модели: opus, затем astra — записывается в `substitutions`
```

- Лимиты отказавшего аккаунта читаются заново. Если применимый лимит исчерпан, аккаунт отдыхает до его сброса.
  Если запас ещё есть, отказ был перегрузкой или кратковременным ограничением — пауза две минуты и только для
  этой модели.
- Паузы хранятся в `~/.local/state/agentgate/accounts.json`, поэтому их видят параллельные сессии `/dev` и
  следующие запуски.
- **Модель меняется только после отказа всех аккаунтов.** Другой аккаунт даёт то же качество, другая модель —
  нет.
- Писатель или ревьюер, которого продолжают (ответ на блокер, исправление, повторная проверка), возвращается
  на аккаунт, где живёт его сессия. Если тот исчерпан, та же сессия продолжается под другим аккаунтом того же
  провайдера; на другую модель она не переходит никогда.

Аккаунт, на котором отработала полоса, записывается вместе с маршрутом и виден в `agentgate watch` как `@имя`.

## Что при этом затрагивается

- Чтение лимитов Claude — один GET к usage-эндпоинту Anthropic с OAuth-токеном самого профиля. `agentgate`
  токен никогда не обновляет: им владеет CLI. Профиль с устаревшим токеном показывает «limits unknown» и
  остаётся рабочим — CLI обновит токен при следующем вызове.
- Чтение лимитов Codex — запрос к локальному `codex app-server` этого профиля.
- Внутри песочницы хост доступен только на чтение, с одним исключением: файл входа выбранного профиля
  (`.credentials.json` или `auth.json`). Когда CLI обновляет токен во время работы, новый токен должен попасть
  в профиль, иначе профиль окажется разлогинен.
- `agentgate doctor` перечисляет аккаунты и показывает, может ли каждый брать работу.
