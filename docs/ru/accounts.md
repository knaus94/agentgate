# Аккаунты и лимиты

[English](../accounts.md)

Аккаунт — это локальный профиль входа для установленного CLI `claude` или `codex`. Несколько профилей
позволяют `agentgate` распределять воркеров между подписками одного провайдера и пропускать аккаунты с
исчерпанными лимитами. Выбор аккаунта не меняет запрошенную модель.

| Провайдер | Профиль по умолчанию | Переменная профиля | Файл входа, используемый менеджером аккаунтов |
|---|---|---|---|
| Claude | `~/.claude` | `CLAUDE_CONFIG_DIR` | `.credentials.json` |
| Codex | `~/.codex` | `CODEX_HOME` | `auth.json` |

Если **для конкретного провайдера** не настроен ни один аккаунт, его воркеры используют стандартный профиль
CLI или профиль из переменной окружения. Ротация аккаунтов для этого провайдера отключена, но объявленные
замены моделей остаются доступны. Настройка аккаунтов Claude не отключает стандартный профиль Codex, и
наоборот.

## Настройка профилей

```sh
agentgate accounts discover          # проверить ~/.claude, ~/.claude-*, ~/.codex, ~/.codex-*
agentgate accounts discover --save   # добавить пригодные профили с отдельной квотой
agentgate accounts list              # обновить и показать лимиты настроенных аккаунтов
agentgate accounts list --json       # структурированный вывод для скриптов
```

Поиск и вывод списка могут обращаться к провайдерам за лимитами. Поиск проверяет перечисленные шаблоны в
домашнем каталоге; профили в других местах нужно добавлять явно. Если настроенных аккаунтов нет,
`accounts list` показывает найденные профили и поясняет, что воркеры пока используют стандартные.

Выделите каждой дополнительной подписке отдельный каталог и войдите через её CLI:

```sh
agentgate accounts add claude-2 claude ~/.claude-2
CLAUDE_CONFIG_DIR=~/.claude-2 claude auth login

agentgate accounts add codex-2 codex ~/.codex-2
CODEX_HOME=~/.codex-2 codex login

agentgate accounts list
```

`accounts add` при необходимости создаёт каталог и записывает аккаунт, но не выполняет интерактивный вход.
Относительный путь к каталогу преобразуется в абсолютный. Менеджер читает учётные данные из файлов: вход,
сохранённый только в системной связке ключей или внешнем помощнике, не считается найденным профилем подписки.
Для управляемой ротации нужен файловый профиль, который поддерживает ваш CLI.

`discover --save` пропускает профили без входа, обнаруженные дубликаты, уже настроенные каталоги или имена и
профили с API-ключом. Для поиска дубликатов используется идентификатор провайдера, если он доступен, иначе —
идентификатор, полученный из учётных данных. Это не позволяет доказать, что каждый независимо созданный вход
относится к отдельной подписке. Обнаруженные дубликаты считаются одним аккаунтом при повторах и распределении
параллельной нагрузки; записанные паузы распространяются на них совместно.

```sh
agentgate accounts reset codex-2      # сбросить локальную паузу и кэш, затем перечитать лимиты
agentgate accounts remove codex-2     # убрать запись; каталог профиля останется на месте
```

Сброс не пополняет квоту провайдера и не обходит его ограничения. Аккаунты хранятся только в пользовательской
конфигурации: обычно `~/.config/agentgate/config.json` или `$XDG_CONFIG_HOME/agentgate/config.json`.
Профили настроек, расширения и конфигурация репозитория не могут задавать список `accounts`. Порядок слоёв и
проверки описаны в [настройке](configuration.md).

## Выбор и ротация

Менеджер использует показание лимитов до двух минут и обновляет его, когда наступает объявленный сброс.
Явный вывод списка аккаунтов запрашивает свежие показания. Неудачные проверки тоже ненадолго кэшируются,
чтобы одновременные воркеры не отправляли повторные запросы без необходимости.

При новом вызове учитываются:

1. **Доступная квота маршрута.** Запас определяет самый тесный применимый общий или модельный лимит.
   Небольшой резерв, около 2%, помогает не назначать работу почти исчерпанному аккаунту. Ограничение одной
   модели не исчерпывает остальные; прошедшее окно сброса перестаёт блокировать выбор.
2. **Уже запущенная работа.** Выполняющиеся вызовы текущего процесса `agentgate` снижают оценку аккаунта,
   распределяя параллельные полосы. Это предпочтение планировщика, а не общая система резервирования квоты
   для всех CLI-процессов на машине.
3. **Профиль лида.** При сопоставимом запасе другого аккаунта профиль интерактивного лида получает меньший
   приоритет. Гарантированный объём квоты для лида при этом не резервируется.

Аккаунт с выполненным входом и неизвестными лимитами остаётся кандидатом. «Неизвестно» не означает
«безлимитно»: CLI всё равно может отказать из-за изменившейся авторизации, доступа или квоты.

При распознанном отказе по квоте менеджер перечитывает лимиты аккаунта. Успешная проверка сначала даёт
двухминутную паузу для маршрута. Более поздний сброс исчерпанного применимого окна продлевает паузу и
распространяет её на соответствующую модель или весь аккаунт. Если узнать текущие лимиты не удалось,
запасная пауза составляет пятнадцать минут. Паузы хранятся в `accounts.json` внутри каталога состояния:
обычно `~/.local/state/agentgate` или
`$XDG_STATE_HOME/agentgate`. Их видят другие сессии. Нечитаемое или повреждённое состояние вызывает ошибку,
а не молча заменяется пустым кэшем.

Сначала вызов пробует следующий пригодный аккаунт того же провайдера. Только когда таких аккаунтов не
остаётся, маршрутизация рассматривает настроенные замены моделей. Уже исчерпанные аккаунты пропускаются
без дополнительного неудачного вызова модели. Ошибки входа, некорректный ответ и другие обычные сбои не
разрешают переход на другую модель. См. [маршрутизацию моделей](model-selection.md).

### Продолжение сессии

Продолжаемый воркер сохраняет идентификатор сессии, модель и фактический каталог полосы, включая каталог
ранее сработавшей замены. Его прежний аккаунт предпочтителен, пока пригоден. При необходимости среда
выполнения может попробовать ту же сессию с другим аккаунтом **того же провайдера**; примет ли CLI такую
сессию, зависит от провайдера. Отказ сообщается явно. На другую модель продолжаемая сессия молча не переносится.

Фактический аккаунт записывается вместе с маршрутом и показывается как `@имя` в [watch](watch.md).

## Оплата через API-ключ

Обнаруженные профили с API-ключом не добавляются автоматически и не используются менеджером без явного
`--paid`. Например, после создания API-профиля Codex через его CLI:

```sh
agentgate accounts add codex-api codex ~/.codex-api --paid
```

Для нового вызова пригодные подписки идут раньше разрешённых API-профилей. Продолжение существующей сессии
предпочитает исходный аккаунт, в том числе платный. Адаптер управляемого аккаунта Codex также перепроверяет,
не сменился ли вход по подписке на API-ключ после чтения лимитов.

`--paid` разрешает конкретный управляемый аккаунт, но не задаёт глобальный бюджет. Если для провайдера не
настроены аккаунты, обычная авторизация CLI через окружение остаётся доступной и может приводить к оплате
согласно настройкам провайдера. При явном выборе управляемого аккаунта унаследованные ключи и адреса API
удаляются из окружения, чтобы они не подменили выбранный вход. Поиск аккаунтов Claude сейчас читает OAuth
подписки, а не отдельные API-ключи из оболочки.

## Учётные данные и обновление токенов

Каждый воркер получает приватную копию выбранного файла входа в собственном каталоге полосы и использует
её для обновления токенов. `agentgate` не добавляет монтирование исходного файла входа на запись. CLI
обновляет свою копию обычными файловыми операциями, в том числе атомарной заменой. Отдельного процесса
обновления OAuth в `agentgate` нет.

После завершения процесса, в том числе неудачного, `agentgate` проверяет изменения файла и сохраняет
корректное обновление обратно под блокировкой. Исходник заменяется только тогда, когда он всё ещё совпадает
с начальным снимком. Если параллельный вход или обновление успели его изменить, существующий профиль
сохраняется, обновлённая копия воркера остаётся на диске, а вызов возвращает явный конфликт с путём к копии.
Бесконфликтное параллельное обновление токенов поэтому не гарантируется: проверьте профиль через его CLI,
при необходимости войдите снова и повторите операцию.

Каталог полосы может содержать копии учётных данных и сессии провайдера. Относитесь к каталогу состояния
задач как к профилю входа; не прикладывайте его целиком к issue и не передавайте как диагностический архив.
Песочница ограничивает запись и скрывает приватные каталоги браузера лида, но не является универсальным
хранилищем секретов для всех доступных на чтение файлов хоста.

## Когда лимиты неизвестны

Проверка Claude читает OAuth-токен профиля и отправляет запрос использования; сама она токен не обновляет.
Просроченный токен отображается как `limits unknown`; CLI может обновить его при следующем использовании
профиля. Для Codex запускается локальный `codex app-server` выбранного профиля и запрашиваются его лимиты.
Ни одна из проверок не доказывает, что запрошенная модель доступна аккаунту.

`agentgate doctor` проверяет установку и настроенные аккаунты; подробные окна и примечания к проверкам
показывает `agentgate accounts list`. Версии CLI и форматы ответов провайдеров меняются; успешные локальные
тесты не заменяют проверку настоящего входа и доступа к модели.
