# Работа из Codex и профиль «только Codex»

[English](../codex.md)

Ведущим агентом AgentGate может быть Claude Code (`/dev`), Codex (`$dev`) или любой из них. Для обоих лидов
используются одинаковые состояния задач, проверки, ревью, терминальная панель и работа с worktree.
Установка интеграции лида и выбор маршрутов воркеров связаны между собой, но фактические модели определяет
итоговая конфигурация.

## Установка интеграции лида

```sh
agentgate setup install --lead claude
agentgate setup install --lead codex
agentgate setup install --lead both
agentgate setup doctor
```

`claude` устанавливает `/dev`, `codex` — `$dev`, `both` — обе интеграции. Явный выбор одного лида удаляет
интеграцию AgentGate для другого. Без явного выбора установка использует сохранённый вариант либо
спрашивает при подключённом терминале. Скрипт установки релиза также принимает
`AGENTGATE_LEAD=claude|codex|both`.

Если профиль ещё не выбран, `--lead codex` дополнительно выбирает встроенный профиль воркеров `codex`.
Уже выбранный пользовательский профиль сохраняется. При явном переключении на Claude или обоих лидов
встроенный профиль `codex` отключается, если был активен. Итоговые маршруты показывает `agentgate modes`.

Для Codex установщик записывает:

| Артефакт | Путь по умолчанию | Назначение |
|---|---|---|
| Навык `dev` и политика его вызова | `~/.agents/skills/dev/` | Явный вызов `$dev <задача>` |
| Правило префикса команды | `~/.codex/rules/agentgate.rules` | Разрешение запросить запуск AgentGate вне собственной песочницы Codex |
| Запись Stop-хука | `~/.codex/hooks.json` | Напомнить лиду о незавершённой задаче при попытке закончить ход |

`CODEX_HOME` меняет расположение правил и хуков Codex. Каталог навыка остаётся в домашнем каталоге
пользователя. Установщик предлагает проверить и одобрить Stop-хук AgentGate в Codex через `/hooks`.
Сверяйтесь с установленной версией Codex: наличие записи ещё не означает, что хост включил хук. Команды
задач и панель можно использовать независимо от него.

## Запуск задачи

Откройте новую сессию Codex в репозитории и явно вызовите установленный навык:

```text
$dev исправь ограничение пагинации
$dev -h review переход состояния платежа
```

Лид готовит структурированные запросы и вызывает AgentGate. В отдельном терминале можно наблюдать тот же
рабочий каталог:

```sh
agentgate task watch
agentgate task status --all
```

Инструмент запускает воркеров через bubblewrap, записывает своё состояние и обращается к CLI провайдеров.
Внешняя песочница может запрещать эти операции. При обнаружении ограниченного окружения AgentGate просит
лида записать входные данные в файл и выполнить отдельную команду, например:

```sh
agentgate task launch --file plan.json
```

Устанавливаемое правило содержит префикс `agentgate` и, когда он известен, абсолютный путь исполняемого
файла. Вызывайте его отдельно от конвейеров, heredoc и обёрток оболочки, чтобы хост мог применить правило
к конкретной программе. Политика разрешений и песочницы хоста продолжает действовать; правило не отменяет
ограничения управляемого окружения. Воркеры сохраняют ограничения монтирования AgentGate. Точные границы
чтения, записи и сетевого доступа описаны в [модели безопасности и доверия](../../SECURITY.md).

## Встроенный профиль «только Codex»

Маршруты профиля — это настройки по умолчанию, а не рейтинг моделей или гарантия доступа аккаунта.
Источником таблицы служит [встроенный профиль](../../internal/assets/profiles/codex.json), наложенный на
[базовую конфигурацию](../../internal/assets/config.json). Личные настройки и настройки репозитория могут
изменить эти значения.

| Роль | light | medium | heavy | ultra |
|---|---|---|---|---|
| Контекст | контекст лида | разведчик `terra:medium` | принятая архитектура | принятая архитектура |
| Архитектура | лид | лид | `astra:high` + `sol:xhigh` | `astra:max` + `sol:max`, затем перекрёстная критика |
| Писатели | `sol:medium` | `astra:medium` | `astra:high` | `astra:high` |
| Ревью архитектуры и простоты | лид | `sol:high` | `sol:xhigh` | `sol:xhigh` |
| Ревью корректности | лид | `sol:high` | `sol:xhigh` | `sol:max` + `terra:max` |
| Ревью безопасности | — | — | — | `sol:xhigh` |
| Потолок усилия | `high` | `high` | `max` | `max` |

Остальные роли настроены на `sol:medium` для консультаций, `astra:medium` для UI-дизайна и `terra:high` для
необязательной браузерной проверки. Это пары псевдонима и усилия. Реальные идентификаторы моделей
провайдера находятся в разделе `models` итоговой конфигурации.

Профиль распределяет существенное написание кода и ревью между разными моделями. Во время работы
исключается любая модель, писавшая часть изменения: в том числе неудачный частичный писатель, автор на
предыдущем этапе и модель, использованная как замена. Если подходящего ревьюера не осталось, задача
сообщает об ошибке маршрутизации. Разные псевдонимы одной модели не обеспечивают независимого ревью.

Все стандартные маршруты этого профиля используют Codex. Ревью между разными провайдерами здесь нет,
а параллельные вызовы могут расходовать лимиты одного аккаунта. Настроенные [аккаунты](accounts.md)
позволяют выбирать профиль и переключаться при исчерпании квоты; панель и квитанции показывают фактические
замены. Название пула не гарантирует отдельную оплату или неограниченную параллельность.

## Проверка и настройка профиля

```sh
agentgate config profiles
agentgate config profile codex
agentgate config show
agentgate config validate
agentgate modes
```

Профиль — слой под явными настройками. Например, эта команда меняет усилие backend-писателя в medium,
сохраняя настроенную модель:

```sh
agentgate config set modes.medium.backend astra:high
agentgate config validate
agentgate modes
```

`agentgate config profile default` возвращает встроенную смешанную таблицу; явные переопределения
сохраняются. Удалить одно из них можно через `agentgate config unset <ключ>`. Пользовательские профили
находятся в `~/.config/agentgate/profiles/<имя>.json` или соответствующем каталоге `XDG_CONFIG_HOME`.

Проверка конфигурации оценивает синтаксис и связи настроек. Она не обращается к провайдеру, чтобы доказать
доступность модели, уровня усилия или функции подписки. Проверьте установленный CLI и доступные модели,
затем оцените работу на характерных задачах своего репозитория. Полезные наблюдения — время выполнения,
упавшие проверки, раунды исправлений, замечания ревью и соответствие результата требованиям. Профиль
не содержит утверждений о текущих ценах, баллах бенчмарков или сравнительной производительности моделей.

Остальные команды и правила маршрутизации описаны в разделах [о выборе моделей](model-selection.md),
[конфигурации](configuration.md) и [CLI](cli.md).

## Интерактивные вопросы

Лид предпочитает `AskUserQuestion` в Claude Code или штатный инструмент ввода Codex. Форму показывает сам
клиент; отдельного интерфейса вопросов Agentgate не создаёт. Вопросы группируются в пределах лимита инструмента.
Асинхронный запрос остаётся в ожидании, а отмена, пустой ответ и таймаут не считаются согласием. При недоступной
форме используется короткий текстовый вопрос. Уже принятые решения повторно не спрашиваются.

В некоторых версиях Codex вопросы в Default-mode доступны через экспериментальный флаг. Наличие проверяется
командой `codex features list`. Если версия поддерживает флаг и вы хотите его использовать:

```sh
codex features enable default_mode_request_user_input
```

Начните новую сессию Codex или перезапустите его агента в редакторе. ACP-клиент также должен объявлять поддержку
form elicitation: флаг не добавляет интерфейс, которого нет в редакторе. Установщик Agentgate самовольно не
меняет эту глобальную экспериментальную настройку. Команда `/dev` для Claude включает `AskUserQuestion`;
выбранные ведущий CLI и профиль моделей сохраняются.
