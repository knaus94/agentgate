# Работа из Codex и вариант «только Codex»

[English](../codex.md)

`agentgate` можно вести из сессии Claude Code (`/dev`), из сессии Codex (`$dev`) или из любой из них. Гейт,
этапы, проверки, панель, изолированные задачи, аккаунты и расширения одинаковы: ничто из этого не зависит от
того, какой CLI — лид. Отличается установка команды лида, а в варианте «только Codex» — ещё и то, какие
модели выполняют работу.

## Выбор при установке

```sh
agentgate install --lead claude   # /dev в Claude Code; работают модели Claude и Codex (таблица по умолчанию)
agentgate install --lead codex    # $dev в Codex; все воркеры — модели Codex
agentgate install --lead both     # /dev и $dev; таблица по умолчанию
```

Без `--lead` первая установка спрашивает, если есть терминал; `scripts/install.sh` задаёт тот же вопрос либо
берёт `AGENTGATE_LEAD`. Выбор запоминается, поэтому `agentgate update` молча повторяет его. Явный выбор
одного лида убирает установку другого; `--lead both` оставляет оба.

Для Codex установщик записывает три вещи:

| Что | Куда | Зачем |
|---|---|---|
| навык `dev` | `~/.agents/skills/dev/` | `$dev <задача>` в сессии; по ключевым словам он не запускается |
| правило | `~/.codex/rules/agentgate.rules` | позволяет Codex запускать `agentgate` вне собственной песочницы Codex (см. ниже) |
| хук Stop | `~/.codex/hooks.json` | не даёт лиду закончить ход с незавершённой задачей |

Codex не выполняет хук, пока вы его не проверили: один раз откройте сессию Codex и одобрите хук agentgate
командой `/hooks`. Всё остальное работает и без этого шага; хук — страховка.

## Зачем правило

`agentgate` запускает каждого воркера в собственной песочнице (`bwrap`), обращается к провайдерам моделей и
хранит состояние в `~/.local/state/agentgate`. Внутри песочницы Codex ничего из этого невозможно: в ней нельзя
запустить другую песочницу, сеть отключена, домашний каталог доступен только на чтение. Поэтому лид должен
запускать `agentgate` вне своей песочницы, и правило разрешает ровно эту команду, ничего больше:

```
prefix_rule(pattern=["agentgate"], decision="allow")
```

Воркеры остаются в песочнице agentgate, так что писатели и ревьюеры ограничены как прежде. Правило
срабатывает только для простой команды — `agentgate <действие> --file <путь>`, — но не для команды с
конвейером, heredoc или `&&`. Лиду это сообщается, он сначала записывает входные данные в файлы, а если
ошибается, `agentgate` отвечает, что делать, а не падает где-то в глубине.

## Таблица «только Codex»

`agentgate install --lead codex` выбирает встроенный профиль `codex` (`agentgate config profile codex`):

| | light | medium | heavy | ultra |
|---|---|---|---|---|
| Контекст | собственный у лида | разведчик `terra:medium` | разведчик `terra:medium` | разведчик `terra:high` |
| Архитектор | лид | лид | `astra:high` ∥ `sol:xhigh` | `astra:max` ∥ `sol:max`, затем перекрёстная критика |
| Писатели | `sol:medium` | `astra:medium` | `astra:high` | `astra:high` |
| Ревью: архитектура + простота | лид | `sol:high` | `sol:xhigh` | `sol:xhigh` |
| Ревью: корректность | лид | `sol:high` | `sol:xhigh` | `sol:max` ∥ `terra:max` |
| Ревью: безопасность | — | — | — | `sol:xhigh` |
| Потолок усилия | `high` | `high` | `max` | `max` |

Прочие роли: консультации — `sol:medium`, дизайн интерфейса — `astra:medium`, браузерная проверка —
`terra:high`.

### Почему именно так

Публичные данные, ноябрь 2026 (Artificial Analysis Intelligence Index v5.0 в изложении Respan; рекомендации
OpenAI в изложении DataCamp):

| Усилие | Astra | Sol | Terra | Luna |
|---|---|---|---|---|
| max | 57 · $6.24 | 55 · $1.27 | 51 · $0.96 | 28 · $0.15 |
| xhigh | 55 · $3.66 | 52 · $0.76 | 45 · $0.40 | 23 · $0.10 |
| high | 55 · $3.24 | 50 · $0.59 | 42 · $0.26 | 21 · $0.07 |
| medium | 51 · $2.73 | 46 · $0.36 | 38 · $0.17 | 18 · $0.04 |

(балл индекса · стоимость задачи)

- **Astra создаёт, Sol проверяет.** Astra — сильнейшая из четырёх на любом усилии, Sol идёт следом при цене
  в пять раз ниже. Раз сильных моделей две, правило «автор не ревьюит свой код» соблюдается именно этой парой.
  Сам OpenAI для самого сложного кода рекомендует Sol или Astra.
- **Astra нигде не стоит на `xhigh`.** По индексу у неё те же 55 на `high` и на `xhigh` — за большие деньги и
  вдвое более долгое ожидание. Шаг, который что-то даёт, — `max`; на нём работают архитекторы ultra, и туда
  же поднимается застрявшее исправление.
- **Качество Sol определяется усилием**: 46 на medium, 50 на high, 55 на max. Ревьюер читает, а не пишет,
  поэтому высокое усилие стоит ему недорого; ревьюеры работают на `high` и выше.
- **Terra читает.** Она самая быстрая из годных моделей (91–109 токенов в секунду) и дешёвая — то, что нужно
  разведчику, — а OpenAI позиционирует её под работу с интерфейсами, то есть под браузерную проверку. На `max`
  она достигает 51, поэтому в ultra она — второй, другой взгляд на корректность.
- **Luna не используется.** С 28 баллами она вдвое слабее остальных.

### Что слабее, чем в таблице по умолчанию

- **Один вендор.** В таблице по умолчанию код одного вендора проверяет другой, а модели разных семейств
  ошибаются по-разному. Здесь ревьюер — другая модель того же семейства.
- **Один пул лимитов.** Все полосы расходуют подписку Codex. Несколько аккаунтов Codex
  ([аккаунты](accounts.md)) распределяют нагрузку.
- **Нет независимых данных о ревью кода.** Как и для таблицы по умолчанию, выбор ревьюеров выведен из
  результатов по написанию кода и рассуждению.

Профиль — всего лишь слой под вашими настройками: `agentgate config set modes.medium.backend sol:high`
по-прежнему переопределяет одну ячейку, а файл `~/.config/agentgate/profiles/<имя>.json` — это ваш собственный
профиль (`agentgate config profiles` показывает их список).
