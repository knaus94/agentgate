# Командный интерфейс

[English](../cli.md)

У AgentGate два связанных интерфейса. Пользователь начинает задачу командой
`/dev <задача>` в Claude Code или `$dev <задача>` в Codex. Ведущий агент вызывает
структурированные CLI-команды для подготовки, выполнения, проверки и завершения
задачи. Сам CLI также отвечает за установку, диагностику, настройки и наблюдение.

## Как найти нужную команду

```sh
agentgate help
agentgate help task
agentgate help setup install
agentgate launch --help
agentgate --version
```

`help`, `-h` и `--help` показывают справку, не выполняя команду. Справка работает
даже при сломанной конфигурации или отсутствующем входном файле. На уровне CLI
`-h` всегда означает справку. Тяжёлый режим указывается внутри текста запроса
для `parse`/`preview` либо в `/dev -h …`.

Группы объединяют связанные операции. Старые плоские имена сохранены и
возвращают те же результаты:

| Группа | Прежняя форма | Назначение |
|---|---|---|
| `agentgate setup install --lead both` | `agentgate install --lead both` | Установить интеграции ведущего агента |
| `agentgate setup doctor` | `agentgate doctor` | Проверить окружение |
| `agentgate setup update --check` | `agentgate update --check` | Проверить наличие обновления |
| `agentgate task watch` | `agentgate watch` | Открыть живую панель |
| `agentgate task status` | `agentgate status` | Получить состояние задачи |
| `agentgate task stop` | `agentgate stop` | Запросить остановку |
| `agentgate task continue` | `agentgate continue` | Продолжить незавершённые потоки после прерывания |
| `agentgate task launch --plan wallet` | `agentgate launch --plan wallet` | Запустить сохранённый план |

В `setup` также входят `config`, `accounts` и `modes`. В `task` входят команды
протокола ведущего агента — полный список показывает `agentgate help task`.
Планы и инструменты дизайна остаются отдельными верхнеуровневыми командами.

## Установка и настройки

```sh
agentgate setup install --lead both
agentgate setup doctor
agentgate config show
agentgate config validate
agentgate modes
agentgate accounts discover
agentgate accounts discover --save
```

`--lead codex` выбирает ведущий Codex и только Codex-исполнителей;
`--lead claude` — ведущий Claude Code; `--lead both` устанавливает обе интеграции.
Модели, профили, квоты и платные API-аккаунты описаны в разделах
[конфигурация](configuration.md) и [аккаунты](accounts.md).

`config validate` проверяет итоговую конфигурацию с учётом всех уровней и
завершается ошибкой, если она некорректна. Для изменения настроек используются
`config set`, `unset` и `profile`.

## Входные данные задачи

Большинство команд протокола принимают ровно один JSON-объект:

```sh
agentgate task launch --file plan.json
agentgate task launch --file=plan.json
agentgate task launch --plan wallet
agentgate task check --all
```

`--file -` читает объект из stdin. Одновременно указывать `--file` и `--plan`
нельзя. `--plan` доступен только в командах, ожидающих план. Ограничение входа —
16 МиБ. Неизвестные поля, `null`, массивы, второй JSON-объект и посторонний текст
после объекта отклоняются. Неизвестные флаги, неверные подкоманды и лишние
аргументы больше не игнорируются.

`parse` и `preview` принимают текст запроса аргументом, из файла или stdin:

```sh
agentgate parse 'исправь ограничение пагинации'
agentgate preview -- '-h move invoice totals to integer cents'
```

Перед текстом, начинающимся с `-`, нужен разделитель `--`. Текст аргументом и
`--file` одновременно не принимаются. Содержимое запроса обрабатывается как
данные; символы shell внутри него не исполняются.

Ведущему Codex может потребоваться вызвать изменяющую состояние команду отдельно,
передав JSON-файл, чтобы сработало установленное правило разрешений. При
обнаружении ограниченного окружения CLI объясняет нужный способ вызова; подробнее
в разделе [Codex](codex.md).

## Остановка и продолжение

`task stop` отправляет запрос остановки работающей операции. Команда не убивает
произвольный процесс по устаревшему PID-файлу. `task status` показывает текущее
состояние и следующий разрешённый шаг.

У прерванного раунда сохраняются завершённые потоки. После устранения причины
`task continue` запускает незавершённые потоки по записанному плану. Задача на
паузе сначала требует `task resume`; заблокированному исполнителю нужен ответ
через `task answer --file answer.json`. Инструмент не отменяет остановку
пользователя самостоятельно и не придумывает ответ на вопрос исполнителя.

Продолжение не обходит проверки, ревью, разбор замечаний или финальное принятие.

## Панель и сценарии автоматизации

```sh
agentgate task watch
agentgate task watch --all
agentgate task watch --once --no-color
agentgate task watch --json
agentgate task status --all
```

Без терминала на stdin/stdout или при `TERM=dumb` команда `watch` печатает
однократный текстовый снимок и завершается. `--once` явно выбирает этот режим.
`--json` всегда печатает один структурированный снимок; `--all` выбирает все
рабочие копии. В JSON есть `schema_version`, `scope`, `read_only` и `tasks`, а у
задач — фаза, исполнители, проверки, число блокирующих замечаний и следующий шаг.
Снимок не запускает модели и не запрашивает квоты у провайдера.

`NO_COLOR` или `watch --no-color` выключает цвета, сохраняя управление клавишами.
Полная таблица клавиш — в разделе [панель](watch.md).

Команды протокола обычно уже возвращают JSON в stdout. Ошибки идут в stderr.
Справка, руководства, таблицы моделей и аккаунтов, обычный `watch` возвращают
текст. Для структурированных наблюдений есть `accounts --json` и `watch --json`.

| Код выхода | Значение |
|---|---|
| `0` | Запрошенная команда выполнена |
| `1` | Ошибка входных данных, настроек, окружения или выполнения |
| `2` | Объявленные проверки не прошли в команде `check` |

Отдельные Node-инструменты дизайна описывают свои коды в `--help`. Успешный вызов
`status`, `route` или `preview` не означает, что задача прошла контроль качества:
нужно смотреть возвращённую фазу и требования.

## Инструменты дизайна

```sh
agentgate figma --help
agentgate layout --help
agentgate fixtures --help
```

У этих команд собственные парсеры, вывод и подробные параметры. Справка содержит
полный синтаксис экспорта Figma, проверки локальной страницы и GraphQL-фикстур.
Полный процесс описан в разделе [дизайн](design.md).
