# Дизайн

[English](../design.md)

Поток может верстать по макету Figma, а гейт — сказать, получилось ли. Что вычислимо, вычисляют инструменты;
модель читает короткие результаты.


## Управление задачей

Для макетов телефона и планшета явно задавайте `device: "mobile"` и нужный CSS `viewport` в записи design
или `screen.json`. Узкое десктопное окно остаётся десктопом: классический scrollbar gutter может уменьшить
ширину документа. Для планшета используется тот же мобильный режим с его viewport. Это эмуляция Chromium
с touch и одним пикселем снимка на CSS-пиксель, а не проверка физического устройства или Safari.

```json
{"design": [{"screen": ".agentgate/design/mobile", "root": "main.app-container",
             "viewport": "390x844", "device": "mobile", "stream": "web"}]}
```

Сопоставляйте одинаковые внешние границы с учётом padding. Фрейм Content шириной 390 px с отступами по 12 px
соответствует обёртке шириной 390 px, а не её дочернему содержимому шириной 366 px. Обёртка может принадлежать
существующей оболочке: её измерение не требует изменения CSS оболочки. Не компенсируйте gutter добавлением
пикселей к viewport или увеличением допусков. Отчёт показывает режим, viewport, ширину документа, размеры и
padding корня, горизонтальный overflow — это позволяет отличить неверную область сравнения от дефекта.

Для перекрывающихся изображений `map.select` связывает метку слоя с уникальным CSS-селектором внутри root.
Он выбирает элемент даже при неправильной позиции, но не отключает проверку геометрии и стиля. Неоднозначный
селектор — ошибка настройки. Старые краткие обозначения элементов из отчётов поддерживаются, если уникальны.


Начинайте с `agentgate prepare --file <JSON с request>`. Инструмент читает ограниченный каталог Figma,
читающий воркер выбирает узлы содержимого, исследует репозиторий и сохраняет план. Лид решает продуктовые
вопросы и согласует ресурсы; экспорт, разбор CSS и сравнение изображений выполняются вне его сессии.
Писатели получают пакет макета и проверки исходников. Layout-командами, baseline и жизненным циклом стенда
управляет гейт: он возвращает измеренные расхождения через `fix`, а изображения оценивает независимый ревьюер.

Ошибочный контракт измерения исправляется через `replan --plan <имя>` с причиной в update. Исходный снимок
кода и замечания сохраняются, служебные layout-команды заменяются, ревью становится неактуальным.
После реализации новая baseline не снимается. Отсутствующая или несовместимая baseline означает строгую
проверку всех различий. Исключается только неизменное расхождение при том же макете, root, viewport, карте
и допусках. Exit 1 означает измеренное расхождение; exit 2 — невозможность проверки, которую надо устранить
до отправки CSS-правок писателю.

## Ход работы

| Шаг | Кто | Что происходит |
|---|---|---|
| Вход | вы, один раз | `agentgate figma login` открывает окно браузера. Сессия остаётся в профиле в `~/.local/share/agentgate/private`, который не видит ни один воркер. Ни токена, ни файла с куками |
| Выбор | подготовительный воркер | получает ограниченный каталог и выбирает соответствующие узлы содержимого |
| Выгрузка | гейт | импортирует выбранные макеты при запуске |
| План | подготовительный воркер, затем лид | воркер составляет план; лид принимает объём работы и разрешения |
| Замер | гейт | до начала работы страница сравнивается с пакетом: что отличается уже сейчас, задаче не засчитывается |
| Код | писатель потока | читает бриф (около двух тысяч токенов на секцию страницы) и запускает объявленные проверки исходников |
| Проверка | гейт | та же проверка вёрстки как объявленная. Новое расхождение блокирует ревью |
| Оценка | первый ревьюер | видит макет рядом со страницей и ищет то, чего не несут числа |

## Пакет

| Файл | Кто читает | Что внутри |
|---|---|---|
| `brief.md` | писатель, ревьюер | слои как намерение: правила раскладки, шрифт, цвет, токены |
| `frame.png` | писатель, ревьюер | картинка узла |
| `assets/` | писатель | иконки в SVG, картинки в PNG |
| `manifest.json` | гейт | источник, версия файла и дайджест содержимого: перевыгруженный макет делает прежние ревью устаревшими |
| `data/` | только инструменты | дерево узлов в формате REST Figma |

Экземпляр компонента — одна строка брифа, одинаковые соседи — один пункт списка, а положения, которые следуют
из автолейаута, не печатаются. `agentgate figma node <dir> <метка>` печатает один слой целиком.

## Что ловится и чем

| Расхождение | Чем ловится |
|---|---|
| положение, размер, радиус, шрифт, цвет, пропавший элемент | проверка вёрстки, без модели |
| неверная иконка, пропавший градиент или тень, обрезанный текст | ревьюер оси `design`, по двум картинкам |
| исключение, оправдывающее то, что продукту не нужно | тот же ревьюер, читая файл исключений |
| поведение | ревьюер корректности, тесты проекта и, если включена, браузерная проверка |

Проверка вёрстки находит текст по словам, а закрашенный блок — по положению, поэтому разметка в коде не нужна.
Слой судится относительно найденного родителя: съехавшая панель — одна находка, а не по одной на каждого ребёнка.

## Экран и его стенд

Экран — это каталог, а проект один раз описывает свой фронт:

```
.agentgate.json               design.stand: как запускается фронт, один раз на проект
<экраны>/<экран>/screen.json  где экран: url, root и, по желанию, locale, viewport, cookies
<экраны>/<экран>/package/     макет, записанный `agentgate figma pull`
<экраны>/<экран>/fixtures/    записанные ответы GraphQL: состояние, в котором экран показан
<экраны>/<экран>/map.json     что продукт показывает иначе
```

```json
{ "command": ["yarn", "nx", "run", "client:dev"], "ready": "http://localhost:4200",
  "env_file": "env/.env.local", "graphql_env": ["VITE_PUBLIC_GRAPHQL_ENDPOINT", "GRAPHQL_INTERNAL_URL"] }
```

`agentgate layout <экран>` — это всё. Если по адресу `ready` никто не отвечает, команда отдаёт фикстуры экрана
как GraphQL-адрес, запускает `command` с переменными из `graphql_env`, направленными туда, ждёт, сравнивает и
останавливает всё, что запустила; бэкенд за экраном не нужен. В плане экран — это `design [{screen, stream}]`,
и гейт выполняет ту же команду. `agentgate layout <экран> --record <шлюз>` работает с настоящим шлюзом и
сохраняет его ответы как фикстуры.

То, что продукт намеренно показывает иначе, называется в `map.json` экрана, каждая запись с причиной:
`{"ignore": {"<метка>": "почему"}, "dynamic": ["<метка>"]}`.

## Ограничения

`figma pull` работает с доступом на просмотр, читая собственный граф сцены веб-приложения Figma: REST API и
MCP-сервер дают месту зрителя несколько вызовов в месяц. Этот граф — не опубликованный интерфейс: когда Figma
его изменит, команда остановится и скажет, какой части больше нет. Место разработчика (Dev seat) делает
пригодным официальный API.
