# claude-dev

[English](README.md)

**`/dev` для Claude Code: ваша сессия руководит, изолированные воркеры Claude и Codex пишут и проверяют код,
а гейт качества решает, когда задача закончена.**

Вы пишете в Claude Code `/dev добавь ограничение частоты на экспорт`. Ваша сессия становится лидом: читает
код, формулирует бриф, делит работу на потоки. Дальше `claude-dev` запускает писателей и ревьюеров отдельными
процессами на выбранных вами моделях, хранит квитанции обо всём, что они сделали, и не даёт закрыть задачу,
пока нет актуального ревью, проходящих проверок и остаются блокирующие замечания.

```
/dev [-l|-m|-h|-x] <задача>
   │
   ├─ разведка     дешёвая модель один раз составляет карту кода; все следующие воркеры начинают с неё
   ├─ дизайн       heavy, ultra: два независимых дизайна параллельно; лид утверждает один
   ├─ код          по изолированному писателю на поток, волнами; писатели сами запускают объявленные проверки
   ├─ проверки     объявленные проверки идут первыми — ревьюерам не платят за чтение кода, который их не проходит
   ├─ ревью        ревьюеры двух производителей параллельно, каждый на другой модели, чем писатель
   ├─ исправление  упавшие проверки и принятые замечания возвращаются тем же писателям, в их же сессии
   └─ закрытие     только с актуальным ревью, проходящими проверками и без блокирующих замечаний
```

## Зачем

- **Несколько подписок одновременно.** Каждая работа идёт на свою модель, параллельные работы — на разные
  бюджеты (например, Claude Opus, Claude Fable и Codex). Если лимит исчерпан, включается заранее заданная
  замена, и это попадает в отчёт.
- **Сильнейшая модель создаёт, остальные проверяют.** Автор не ревьюит свой код: ревьюеры — свежие процессы
  на других моделях, от двух производителей во всех режимах выше лёгкого.
- **Доказательства, а не заявления.** Ревью и результаты проверок привязаны к точному содержимому файлов.
- **Настоящая изоляция.** Каждый воркер работает в `bwrap` с хостом только для чтения.
- **Дешёвый диалог.** Заблокированному писателю отвечают в его же сессию; исправления получает тот, кто писал
  код; ревьюер перепроверяет только исправление.
- **Одна ручка.** Четыре режима, и режим выбирается автоматически.

## Режимы

Без флага лид записывает факты о задаче — размер, названные риски, обратимость, неопределённость — и режим
следует из фиксированной таблицы правил. Флаг всегда главнее.

| | лёгкий `-l` | средний `-m` | тяжёлый `-h` | сверхтяжёлый `-x` |
|---|---|---|---|---|
| Когда | мелочь, ≤3 файлов, без риска | обычная работа | назван риск, либо сложно и неясно | необратимый риск, либо серьёзный риск в сложной работе |
| Контекст | собственный у лида | разведка `sol:medium` | разведка `sol:medium` | разведка `sol:high` |
| Архитектор | лид | лид | `fable:high` ∥ `astra:high` | `fable:xhigh` ∥ `astra:xhigh`, затем перекрёстная критика |
| Бэкенд | `sol:medium` | `opus:medium` | `fable:high` | `fable:xhigh` |
| Фронтенд | `sonnet:medium` | `opus:medium` | `fable:high` | `fable:xhigh` |
| Ревью: архитектура | лид | `fable:medium` | `opus:high` | `opus:high` |
| Ревью: корректность | лид | `astra:medium` | `astra:high` | `opus:xhigh` ∥ `astra:xhigh` |
| Ревью: безопасность | — | — | — | `astra:high` |
| Потолок усилия | `high` | `high` | `xhigh` | `max` |
| Блокирует | P0–P1 | P0–P1 | P0–P2 | P0–P2 |

В каждой клетке `модель:усилие`. Через таблицу проходят два правила:

- **Создаёт сильнейшая модель, которую режим может себе позволить; остальные фронтирные модели проверяют.**
- **Усилие тратится там, где окупается.** Дешёвая разведка один раз читает репозиторий, поэтому дорогие
  модели рассуждают, а не исследуют. Средний режим запускает каждую модель на уровне, который производитель
  ставит по умолчанию, тяжёлый — на ступень выше, сверхтяжёлый — на две. `max` никогда не стоит по умолчанию:
  он включается, только когда исправление не дало прогресса или лид поднял усилие одному трудному потоку.
  Перепроверка после исправления идёт на ступень ниже и только по полосам, которым есть что проверять.

Выбор следует публичным данным о бенчмарках, ценах и рекомендациям производителей — см.
[Почему именно эти модели](docs/ru/model-selection.md) — и любую клетку можно
[заменить](docs/ru/configuration.md).

## Установка

Linux, x86-64 или arm64. Нужны Claude Code, Codex CLI, `bwrap` (bubblewrap), `git` и `diff`.

```sh
curl -fsSL https://raw.githubusercontent.com/knaus94/claude-dev/main/scripts/install.sh | sh
```

Скрипт скачивает бинарник в `~/.local/bin`, сверяет контрольную сумму и запускает `claude-dev install`,
который добавляет в Claude Code команду `/dev` и Stop-хук.

```sh
claude-dev doctor     # проверить окружение
claude-dev modes      # какая модель что делает
claude-dev update     # обновиться до последней версии
```

Откройте новую сессию Claude Code и наберите `/dev help`.

## Использование

```
/dev исправь смещение на единицу в пагинации заказов
/dev -h переведи суммы счетов в целые копейки
/dev -2 review --fix изменения в этой ветке
/dev plan -x раздели сервис кошелька
/dev status      /dev stop      /dev help
```

`-N` ограничивает число одновременных процессов. `--preview` показывает, что запустится, ничего не запуская.
`plan`, `research` и `verify` только читают. `review` оценивает готовый дифф; `--fix` разрешает исправлять.

Живая панель задачи — в любом терминале внутри репозитория: `claude-dev watch`.
Для Zed: `claude-dev install --zed` добавит задачи `claude-dev: watch`, `status` и `stop`.

План задачи хранится в репозитории, в `.claude-dev/plans/<имя>/`: `plan.json` — то, что запускается,
`brief.md` — тот же план для чтения человеком. `claude-dev plan list` показывает сохранённые планы; план можно
запустить из более поздней сессии.

## Несколько подписок

```sh
claude-dev accounts discover --save   # подхватить все профили CLI на машине, в которых выполнен вход
claude-dev accounts                   # текущие лимиты каждого аккаунта
```

Когда подписок Claude или Codex несколько, воркеры распределяются по аккаунтам по остатку квоты, аккаунт,
упёршийся в лимит, отдыхает до сброса, а модель заменяется только после отказа всех аккаунтов. Подробнее:
[docs/ru/accounts.md](docs/ru/accounts.md).

## Настройка моделей

```sh
claude-dev config init                               # создать ~/.config/claude-dev/config.json
claude-dev config set models.sol.model gpt-6.1-sol   # привязать псевдоним к другой модели
claude-dev config set modes.medium.backend sonnet:high  # поменять, кто что делает
claude-dev config show
```

Репозиторий может иметь свой `.claude-dev.json`.
