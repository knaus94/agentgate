# AgentGate

[English](README.md) · [Команды](docs/ru/cli.md) · [Архитектура](docs/architecture.md) · [Изменения версии](RELEASE_NOTES.md)

**Локальный оркестратор и гейт качества для работников Claude Code и Codex.** Ведущая сессия принимает
задачу и решения; AgentGate запускает работников, фиксирует результаты, выполняет проверки и независимое
ревью. Завершить задачу можно только при актуальных доказательствах качества.

Это Linux CLI с живой терминальной панелью. Постоянный сервер и облачный сервис не нужны. Используются
настроенные вами CLI и аккаунты провайдеров. Поддерживается переход со старого имени `claude-dev`.

## Быстрый запуск из архива

В архиве есть исходники, документация, SHA-256 и готовые бинарники для Linux x86-64 и arm64.
После распаковки:

```sh
cd agentgate-0.14.0
sh scripts/install-local.sh --lead both
agentgate setup doctor
agentgate config validate
agentgate modes
```

Выберите `--lead codex`, `--lead claude` или `--lead both`. Вариант Codex выбирает встроенный профиль
работников `codex`, если профиль ещё не задан; выбранный пользовательский профиль сохраняется.
`--no-integrations` копирует только бинарник. Локальный установщик ничего не скачивает и не требует root;
каталог установки должен быть доступен для записи и добавлен в `PATH`.

Нужны Linux или WSL2, `git`, `diff`, `bubblewrap` (`bwrap`) и CLI провайдеров выбранного профиля. Войдите
в эти CLI самостоятельно. Для дополнительных дизайн-проверок нужны Node.js 20+, `playwright-core` и Chromium.

Сборка из исходников — `make build` с Go 1.25+. У Go-части нет внешних модулей. Бинарник будет в
`dist/agentgate`. Онлайн-установщик `scripts/install.sh` продолжает работать с опубликованными релизами
GitHub. Локально выданный архив может опережать GitHub: проверяйте версии перед `agentgate update`.

## Как пользоваться

После установки откройте новую ведущую сессию:

```text
/dev add rate limiting to the export endpoint     Claude Code
$dev add rate limiting to the export endpoint     Codex

/dev -h move invoice totals to integer cents      явный heavy
/dev -w add pagination to the orders list         отдельный worktree
/dev -2 review --fix the current branch changes   максимум два работника
/dev plan -x split the wallet service             сначала план
```

Лид готовит и принимает план, затем управляет процессом структурированными командами. `--preview`
показывает предполагаемую работу. `plan`, `research` и `verify` ничего не изменяют. `review` проверяет
существующие изменения; `--fix` разрешает их исправлять.

| Этап | Действие | Что остаётся в качестве доказательства |
|---|---|---|
| Подготовка | Разведка, границы задачи, план | Проверенный план и критерии приёмки |
| Разведка / архитектура | Контекст или независимые предложения по режиму | Карта кода или принятый дизайн |
| Реализация | Потоки с раздельными файлами, волны зависимостей | Отчёты работников и аудит области изменений |
| Проверки | Команды до запуска ревьюеров | Код выхода, журнал, отпечаток входных файлов |
| Ревью | Отдельные модели проверяют результат | Замечания и ревью, привязанные к коду и договорённостям |
| Исправление | Исходный автор продолжает свою сессию | Новая попытка в правильном контексте провайдера |
| Завершение | Гейт проверяет все условия | Актуальное ревью, зелёные проверки, отсутствие блокеров |

Падение проверки до начала задачи помогает диагностике, но не разрешает игнорировать последующие
падения. Изменения кода или условий приёмки делают соответствующие результаты устаревшими. Модель
автора не может ревьюить свой код: учитываются предыдущие этапы и частично неудачные попытки.

## Команды

| Задача | Команда |
|---|---|
| Найти нужную команду | `agentgate help`, `agentgate help task` |
| Установка и диагностика | `agentgate setup install --lead both`, `agentgate setup doctor` |
| Настройки | `agentgate config show`, `agentgate config validate` |
| Наблюдение | `agentgate task watch`, `agentgate task status --all` |
| Панель в JSON для скриптов | `agentgate task watch --json` |
| Остановка | `agentgate task stop` |
| Продолжение прерванного раунда | `agentgate task resume`, затем `agentgate task continue` |
| Сохранённые планы | `agentgate plan list`, `agentgate task launch --plan <name>` |
| Аккаунты | `agentgate accounts`, `agentgate accounts discover --save` |
| Модели | `agentgate modes` |
| Дизайн-инструменты | `agentgate figma --help`, `agentgate layout --help`, `agentgate fixtures --help` |

Старые плоские команды продолжают работать. `--help` всегда только показывает справку, в том числе
у install, stop и update. Неизвестные флаги, конфликтующие источники ввода, некорректный JSON и лишний
ввод отвергаются. [Полная справка CLI](docs/ru/cli.md).

## Терминальная панель

```sh
agentgate task watch
agentgate task watch --once --no-color
agentgate task watch --json
```

В панели видны задачи, этапы и их время, работники, проверки и замечания. Стрелки или `j/k` перемещают
выбор, Enter открывает детали, Escape возвращает назад, `r` обновляет, `?` показывает подсказки. Узкий
терминал поддерживается; выбранная строка остаётся в видимой области. `NO_COLOR` отключает цвет.
Управляющие последовательности из журналов не могут вмешиваться в управление терминалом. При
перенаправлении ввода/вывода и `TERM=dumb` выводится один снимок. [Панель подробнее](docs/ru/watch.md).

## Режимы и модели

| Режим | Когда подходит | Архитектура | Ревью | Блокирует завершение |
|---|---|---|---|---|
| light `-l` | Небольшая правка без риска | Лид | Лид | P0–P1 |
| medium `-m` | Обычная реализация | Лид и разведка | Независимые настроенные полосы | P0–P1 |
| heavy `-h` | Названный риск или сложность с неопределённостью | Два предложения | Архитектура и корректность | P0–P2 |
| ultra `-x` | Серьёзный или необратимый риск | Предложения и взаимная критика | Дополнительная корректность и безопасность | P0–P2 |

Без флага режим выбирается по фиксированным правилам из записанной оценки. Явный флаг важнее автооценки.
В смешанном профиле модели авторов отделены от Fable/Astra, выполняющих ревью. Есть профиль только для
Codex. Это настраиваемые стартовые конфигурации, а не универсальный рейтинг качества моделей.
[Политика маршрутизации](docs/ru/model-selection.md).

```sh
agentgate config set modes.medium.backend sol:high
agentgate config set modes.medium.frontend sol:high
agentgate config validate
```

## Аккаунты, изоляция и восстановление

Работники распределяются по настроенным CLI-профилям с учётом известных лимитов. Истёкшее окно квоты
не блокирует аккаунт навсегда. Неудачный опрос не изображает свежие данные. Для выбранного аккаунта
создаётся приватная копия учётных данных; обновление токена сверяется с оригиналом и не перезаписывает
параллельный вход в аккаунт. [Аккаунты](docs/ru/accounts.md).

`bwrap` делает хост доступным только для чтения, даёт собственные временные каталоги и открывает запись
писателю в checkout. Файлы между писателями разделяются назначением и последующим аудитом. Это
ограничение записи для доверенной локальной разработки; оно не обещает полной защиты секретов от
враждебного кода. Точная граница описана в [SECURITY.md](SECURITY.md).

С `-w` задача работает в собственном worktree. Перенос изменений проверяет область задачи и не включает
посторонние staged-файлы. После остановки сохраняется состояние; продолжение запускает только
незавершённые потоки. [Worktree](docs/ru/isolation.md) · [Переход на новую версию](docs/migration.md).

## Figma, сравнение вёрстки и GraphQL-фикстуры

Дизайн-модуль выгружает пакеты, сравнивает страницу с ними и запускает локальный стенд с записанными
ответами GraphQL. Пакет заменяется только после полной выгрузки. Инвентарь файлов обнаруживает изменения
и недостающие части. Отсутствующая фикстура явно возвращает ошибку, если вы отдельно не разрешили пустые
данные.

Два способа чтения Figma:

- **Официальный REST API:** `FIGMA_ACCESS_TOKEN` со scope `file_content:read`, либо `--transport api`.
  Рендеры привязаны к загруженной версии файла. При лимите API показывается ошибка; скрытой смены
  транспорта нет.
- **Браузерная сессия:** `agentgate figma login`, затем `--transport browser`. Прежний сценарий сохранён,
  но внутренний scene graph Figma может изменяться: это явно обозначенный адаптер совместимости.

Токен Figma не попадает в пакет. Измерение геометрии и независимая визуальная приёмка остаются разными
проверками. [Дизайн-процесс](docs/ru/design.md).

## Проверка и сборка

```sh
make check
npm ci --prefix design-kit --ignore-scripts --no-audit --no-fund
node design-kit/node_modules/playwright-core/cli.js install chromium
make design-browser
make package
```

`make check` выполняет форматирование, vet, Go-тесты с race detector и основные Node-сценарии.
`make design-browser` требует запуска Chromium. `make package` собирает оба Linux-бинарника и ZIP
с исходниками и контрольными суммами.

Go-интеграционные тесты используют управляемые имитации CLI провайдеров: они проверяют запуск, проверки,
ревью, исправление и завершение без расхода подписок. Это не подтверждение доступности модели в живом
аккаунте. [Протокол проверки архива](docs/validation.md) отдельно перечисляет выполненные проверки и
ограничения среды.
