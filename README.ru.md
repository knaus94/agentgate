# AgentGate

[English](README.md) · [Команды](docs/ru/cli.md) · [Архитектура](docs/architecture.md) · [Изменения версии](RELEASE_NOTES.md)

**Локальный гейт качества для работы в Claude Code и Codex.** Ваша сессия сама планирует задачу и пишет её
небольшими стадиями; AgentGate держит её в рамках плана: запускает объявленные проверки, даёт второй модели
прочитать план и код там, где это задаёт режим, и разрешает завершить задачу только при актуальных
доказательствах. Вместо сессии работу могут делать писатели в песочнице — с `--workers`.

Это Linux CLI с живой терминальной панелью. Постоянный сервер и облачный сервис не нужны. Используются
настроенные вами CLI и аккаунты провайдеров. Поддерживается переход со старого имени `claude-dev`.

## Быстрый запуск из архива

В архиве есть исходники, документация, SHA-256 и готовые бинарники для Linux x86-64 и arm64.
После распаковки:

```sh
cd agentgate-0.22.0
sh scripts/install-local.sh --lead both
agentgate setup doctor
agentgate config validate
agentgate modes
```

Выберите `--lead codex`, `--lead claude` или `--lead both`. Вариант Codex выбирает встроенный профиль
работников `codex`, если профиль ещё не задан; выбранный пользовательский профиль сохраняется.
`--no-integrations` копирует только бинарник. Локальный установщик ничего не скачивает и не требует root;
каталог установки должен быть доступен для записи и добавлен в `PATH`.

Нужны Linux или WSL2, `git`, `diff`, `bubblewrap` (`bwrap`) и CLI провайдеров выбранного профиля. Войдите
в эти CLI самостоятельно. Для дополнительных дизайн-проверок нужны Node.js 20+, `playwright-core` и Chromium.

Сборка из исходников — `make build` с Go 1.25+. У Go-части нет внешних модулей. Бинарник будет в
`dist/agentgate`. Онлайн-установщик `scripts/install.sh` продолжает работать с опубликованными релизами
GitHub. Локально выданный архив может опережать GitHub: проверяйте версии перед `agentgate update`.

## Как пользоваться

После установки откройте новую ведущую сессию:

```text
/dev add rate limiting to the export endpoint     Claude Code
$dev add rate limiting to the export endpoint     Codex

/dev -l rename the export flag                    light: план, стадии и проверки, без других моделей
/dev -h move invoice totals to integer cents      heavy: записанный дизайн и независимые читатели
/dev review --fix the current branch changes      прочитать готовое изменение и исправить найденное
/dev plan -x split the wallet service             только план
/dev --workers -w add pagination to the orders list   писатели в песочнице, в отдельном worktree
```

Каждая задача начинается с плана. Сессия спрашивает вас о том, чего нет в коде, находит ближайшую
существующую реализацию каждой части и пишет план из небольших стадий по порядку; выше light план читает
вторая модель, которой показан разговор, и вы одобряете его, видя цену — сколько запусков моделей он начнёт
помимо самой сессии. Дальше сессия пишет по одной стадии, а `agentgate run` закрывает каждую: проверяет
область, запускает проверки стадии и сканирует добавленные строки — без моделей. Код читает читатель режима
на контрольных точках, которые отмечает план, и после последней стадии. `--preview` показывает предполагаемую
работу. `plan`, `research` и `verify` ничего не изменяют. `review` проверяет существующие изменения;
`--fix` разрешает их исправлять.

| Шаг | Действие | Что остаётся в качестве доказательства |
|---|---|---|
| План | Сессия уточняет задачу, привязывает изменение к существующему коду и пишет типизированный план | План, проверенный целиком, все проблемы названы сразу; чему следует каждая стадия; цена |
| Чтение плана (medium и выше) | Советник читает план вместе с разговором; в heavy и ultra дизайн сессии читают независимые критики | Блокеры, на которые отвечает сессия; отклонённый ею уходит к вам |
| Реализация | Сессия пишет открытую стадию и ничего из следующих | Её отчёт и аудит каждого файла, изменённого вне плана |
| Проверки | Объявленные команды запускает инструмент, до любого читателя | Код выхода и журнал, привязанные к дереву, на котором они шли |
| Чтение кода | На контрольной точке и после последней стадии: сама сессия (light), советник (medium), независимые полосы (heavy, ultra) | Замечания и вердикты, привязанные к коду и договорённостям |
| Исправление | Блокирующее замечание возвращается сессии: она исправляет или оспаривает с доказательствами | Ответ читателя в его же сессии |
| Приёмка | Стадия, а затем задача принимаются в том же запуске, как только всё требуемое актуально | Зелёные проверки, актуальное чтение там, где оно назначено, подтверждённые требования; квитанция с расходом |

С `--workers` тот же гейт ведёт писателей в песочнице: план готовит работник с доступом только на чтение,
проектируют архитекторы, каждый поток пишет свой писатель, и каждая стадия проходит ревью.
[Как это устроено](docs/ru/how-it-works.md).

Падение проверки до начала задачи помогает диагностике, но не разрешает игнорировать последующие
падения. Изменения кода или условий приёмки делают устаревшим ровно то, что они затрагивают. План
можно поправить на любом шаге, не теряя задачу. [Почему так устроено](docs/decisions/README.md).

## Команды

| Задача | Команда |
|---|---|
| Найти нужную команду | `agentgate help`, `agentgate help task` |
| Установка и диагностика | `agentgate setup install --lead both`, `agentgate setup doctor` |
| Настройки | `agentgate config show`, `agentgate config validate` |
| Наблюдение | `agentgate task watch`, `agentgate task status --all` |
| Панель в JSON для скриптов | `agentgate task watch --json` |
| Остановка | `agentgate task stop` |
| Продолжение после прерывания | `agentgate task run` |
| Сохранённые планы | `agentgate plan list`, `agentgate task start --plan <name>` |
| Аккаунты | `agentgate accounts`, `agentgate accounts discover --save` |
| Модели | `agentgate modes` |
| Дизайн-инструменты | `agentgate figma --help`, `agentgate layout --help`, `agentgate fixtures --help` |

Старые плоские команды продолжают работать. `--help` всегда только показывает справку, в том числе
у install, stop и update. Неизвестные флаги, конфликтующие источники ввода, некорректный JSON и лишний
ввод отвергаются. [Полная справка CLI](docs/ru/cli.md).

## Терминальная панель

```sh
agentgate task watch
agentgate task watch --once --no-color
agentgate task watch --json
```

В панели видны задачи, этапы и их время, работники, проверки, замечания и лимиты каждого аккаунта по
именам. Стрелки или `j/k` перемещают
выбор, Enter открывает детали, Escape возвращает назад, `r` обновляет, `?` показывает подсказки. Узкий
терминал поддерживается; выбранная строка остаётся в видимой области. `NO_COLOR` отключает цвет.
Управляющие последовательности из журналов не могут вмешиваться в управление терминалом. При
перенаправлении ввода/вывода и `TERM=dumb` выводится один снимок. [Панель подробнее](docs/ru/watch.md).

## Четыре режима: форма процесса

Режим не выбирает писателю модель посильнее: пишет ваша сессия. Он задаёт, насколько подробен план и какой
второй взгляд получает работа.

| Режим | План | План читает | Код читает | Запусков моделей помимо сессии |
|---|---|---|---|---|
| light `-l` | стадии и проверки; старт сразу | никто | сама сессия, с доказательством на каждое требование | 0 |
| medium `-m` (по умолчанию) | чему следует каждая стадия, карта области; вы одобряете | советник, которому показан разговор | советник, на контрольных точках и в конце | 2 и по одному на контрольную точку |
| heavy `-h` | плюс записанный дизайн | советник и независимый критик | независимые полосы, в том числе на каждой стадии со своим риском | 2 и две полосы на каждое чтение |
| ultra `-x` | плюс исполняемое доказательство того, что завершает рискованная стадия | то же; критик сначала проектирует вслепую | четыре полосы | 3 и четыре полосы на каждое чтение |

Без флага режим — medium. Оценка плана его не поднимает: инструмент говорит, что следует из фактов, а решаете
вы. `agentgate modes` печатает действующую таблицу — для задачи, которую пишет сессия, и для `--workers`.
Читатели и советник — маршруты из конфигурации; есть профиль только для Codex. Это настраиваемые стартовые
конфигурации, а не универсальный рейтинг качества моделей.
[Правила режимов](docs/ru/modes.md) · [Политика маршрутизации](docs/ru/model-selection.md).

```sh
agentgate config set advisor fable:xhigh
agentgate config set executor workers        # по умолчанию писатели в песочнице
agentgate config validate
```

## Аккаунты, изоляция и восстановление

Работники распределяются по настроенным CLI-профилям с учётом известных лимитов. Истёкшее окно квоты
не блокирует аккаунт навсегда. Неудачный опрос не изображает свежие данные. Аккаунт можно оставить лиду
(`accounts reserve <имя>`): работники на нём не запускаются. Собственный лимит модели, например Fable,
учитывается только для этой модели. Для выбранного аккаунта
создаётся приватная копия учётных данных; обновление токена сверяется с оригиналом и не перезаписывает
параллельный вход в аккаунт. [Аккаунты](docs/ru/accounts.md).

`bwrap` делает хост доступным только для чтения, даёт собственные временные каталоги и открывает запись
писателю в checkout. Файлы между писателями разделяются назначением и последующим аудитом. Это
ограничение записи для доверенной локальной разработки; оно не обещает полной защиты секретов от
враждебного кода. Точная граница описана в [SECURITY.md](SECURITY.md).

С `--workers -w` задача работает в собственном worktree; задача, которую пишет сессия, работает в вашем checkout. Перенос изменений проверяет область задачи и не включает
посторонние staged-файлы. После остановки сохраняется состояние; `run` запускает только незавершённые
потоки. Задача, сохранённая версией 0.15, читается и продолжается как есть. [Worktree](docs/ru/isolation.md) · [Переход на новую версию](docs/migration.md).

## Figma, сравнение вёрстки и GraphQL-фикстуры

Дизайн-модуль выгружает пакеты, сравнивает страницу с ними и запускает локальный стенд с записанными
ответами GraphQL. Пакет заменяется только после полной выгрузки. Инвентарь файлов обнаруживает изменения
и недостающие части. Отсутствующая фикстура явно возвращает ошибку, если вы отдельно не разрешили пустые
данные.

Два способа чтения Figma:

- **Официальный REST API:** `FIGMA_ACCESS_TOKEN` со scope `file_content:read`, либо `--transport api`.
  Рендеры привязаны к загруженной версии файла. При лимите API показывается ошибка; скрытой смены
  транспорта нет.
- **Браузерная сессия:** `agentgate figma login`, затем `--transport browser`. Прежний сценарий сохранён,
  но внутренний scene graph Figma может изменяться: это явно обозначенный адаптер совместимости.

Токен Figma не попадает в пакет. Измерение геометрии и независимая визуальная приёмка остаются разными
проверками. [Дизайн-процесс](docs/ru/design.md).

## Проверка и сборка

```sh
make check
npm ci --prefix design-kit --ignore-scripts --no-audit --no-fund
node design-kit/node_modules/playwright-core/cli.js install chromium
make design-browser
make package
```

`make check` выполняет форматирование, vet, Go-тесты с race detector и основные Node-сценарии.
`make design-browser` требует запуска Chromium. `make package` собирает оба Linux-бинарника и ZIP
с исходниками и контрольными суммами.

Go-интеграционные тесты используют управляемые имитации CLI провайдеров: они проводят задачи целиком —
реализацию, проверки, ревью, исправление, поправку плана и завершение — без расхода подписок. Это не подтверждение доступности модели в живом
аккаунте. [Протокол проверки архива](docs/validation.md) отдельно перечисляет выполненные проверки и
ограничения среды.
